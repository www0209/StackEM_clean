## 2. 核训练集是什么

### 2.1 核

一条轨由许多段组成。对单独一段来说，应力方程是线性的，所以这一段对任何激励的响应都可以由三个基本响应叠加出来。这三个基本响应称为核。

| 核 | 含义 |
|---|---|
| `s_G` | 电迁移激励下的响应，两端封死 |
| `s_M` | 热迁移激励下的响应，两端封死 |
| `a` | 在一端注入单位通量时的响应 |

每个核都是段内位置和时间的函数，并且随这一段的温度状况变化。代码把温度状况压缩成四个无量纲的量，写作 `theta`、`r`、`rho_J`、`lam`，分别反映平均温度、两端温差、焦耳自热幅度、段长与热特征长度之比。

### 2.2 数据集的构成

`kernels` 这一步用参考求解器为大量随机的温度状况逐个算出三个核，作为网络的训练数据。一种温度状况称为一个剖面。

| 项目 | 数值 |
|---|---|
| 剖面数 | 120000 |
| 每个剖面保留的采样点 | 128 个，其中 32 个固定取在段的两端，因为闭合只在端点处查核 |
| 总行数 | 15360000 |
| 每行的输入 | 6 个数：`xi` 段内位置，`log10_tau` 无量纲时间的对数，以及 `theta`、`r`、`rho_J`、`lam` |
| 每行的目标 | 3 个数：三个核各除以时间的平方根。这样缩放后，网络在极短时间处的相对精度才有保证 |
| 平均温度的取值范围 | 300 到 450 K |
| 段两端温差的范围 | 正负 12 K |
| 焦耳温升幅值的范围 | 0 到 40 K，其中三成的剖面取 0 |
| `log10_lam` 的范围 | 负 0.5 到 2.1 |
| `log10_tau` 的范围 | 负 6 到 1 |
| 参考求解器每段的单元数 | 200 |
| 随机种子 | 2027，固定 |

这些范围覆盖了堆叠流程可能产生的所有段，并留有余量。数据集与任何具体的堆叠、网表、轨宽都无关，所以只需要生成一次，三个堆叠算例和 IBM 基准共用同一个网络。

同一步还生成两个留出集，专供 E1 评估用，不参与训练。

| 文件 | 内容 |
|---|---|
| `kernels_train.npz` | 上述训练集，约 330 MB |
| `kernels_val_full.npz` | 400 个训练范围之内的剖面，保存完整的核曲面 |
| `kernels_ood_full.npz` | 100 个训练范围之外的剖面：平均温度 450 到 480 K，焦耳温升 40 到 60 K，两端温差正负 20 K |
| `dataset_info.json` | 取值范围和材料参数的记录 |

三个 `.npz` 文件都在 `~/stackem_work/outputs/base3/kernels/`。

### 2.3 运行时屏幕上是什么样

```text
  6000/120000 profiles, 13 s elapsed, eta 253 s
  12000/120000 profiles, 25 s elapsed, eta 229 s
  ...
  120000/120000 profiles, 211 s elapsed, eta 0 s
saved .../base3/kernels/kernels_train.npz: X (15360000, 6), Y (15360000, 3), 222 s
```

这是参考机用 32 个线程的输出。这一步完全由处理器完成，核数少的机器耗时大致按线程数的比例增加。`eta` 是预计剩余时间。

## 3. 训练教师网络

`train_teacher` 这一步读入 `kernels_train.npz`，训练一个全连接网络。

| 项目 | 数值 |
|---|---|
| 结构 | 6 个隐藏层，每层 256 个神经元，SiLU 激活，24 个傅里叶特征 |
| 参数量 | 343811 |
| 训练行数与验证行数 | 14592000 与 768000。按剖面划分，百分之五的剖面留作验证 |
| 轮数 | 300 |
| 批大小 | 8192 |
| 学习率 | 最大 0.001，余弦下降到 0.00001，前 5 轮预热 |
| 损失 | 只有数据项，方程残差项的权重 `w_pde` 为 0 |
| 提前停止 | 验证误差连续 40 轮没有改善时停止。参考机的那次训练跑满了 300 轮 |
| 随机种子 | 0 |

屏幕上每轮打印一行：

```text
epoch    0 lr 2.00e-04 mse 3.107e-01 pde 0.000e+00 val rel-L2 [sG 1.87e-01 sM 4.02e-01 a 7.35e-02] 5s
...
epoch  299 lr 1.00e-05 mse 1.961e-06 pde 0.000e+00 val rel-L2 [sG 1.07e-03 sM 1.82e-03 a 6.34e-04] 1345s
done. best val worst-target rel-L2 1.817e-03 at epoch 295; torch-vs-numpy max diff 1.94e-05
```

各列依次是轮数、学习率、训练损失、方程残差、三个核在验证集上的相对误差、累计秒数。`val rel-L2` 里的三个数应当随训练从 0.1 的量级降到 0.001 的量级。参考机上最好的一轮是第 295 轮，三个核里最差的那个的相对误差是 0.0018。最后一行的 `torch-vs-numpy max diff` 是导出的权重用 numpy 计算与 PyTorch 计算的差，应当在 0.00001 的量级。

`done.` 一行之前可能出现一条 `RuntimeWarning: overflow encountered in exp`，参考机的日志里也有，它不影响结果。

输出在 `~/stackem_work/outputs/base3/skn/`：

| 文件 | 内容 |
|---|---|
| `skn_best.npz` | 验证误差最小的那一轮的权重，后续所有步骤使用这个文件 |
| `skn_last.npz` | 最后一轮的权重，后续步骤不使用 |
| `train_log.csv` | 每轮一行的训练记录 |
| `train_curves.png` | 损失和验证误差曲线 |
| `train_summary.json` | 最好轮次、最好误差、参数量和全部训练参数 |

## 4. 蒸馏学生网络

教师网络精度高，但一个堆叠要查核上千万到上亿次，用它太慢。`distill` 这一步训练一个小得多的学生网络来代替它。

| 项目 | 数值 |
|---|---|
| 结构 | 4 个隐藏层，每层 128 个神经元，16 个傅里叶特征 |
| 参数量 | 54915，约为教师的 6.3 分之一 |
| 训练数据 | 参考求解器的 14592000 行，加上由教师网络标注的 8000000 个点，共 22592000 行 |
| 教师标注点的分布 | 七成取在段的两端，其余在段内均匀分布 |
| 验证 | 用留出的 768000 行参考求解器数据，不用教师的输出。所以报告的精度是对物理的精度 |
| 轮数 | 150 |
| 批大小 | 16384 |
| 学习率 | 最大 0.002，余弦下降到 0.00001，前 2 轮预热 |
| 提前停止 | 30 轮 |

屏幕输出：

```text
device cuda; FDM rows 14,592,000 + teacher-labelled 8,000,000 = 22,592,000; val rows 768,000 (197,693 at the ends)
teacher (343,811 params): val rel-L2 [0.00109 0.00182 0.00064], at the ends [0.0006  0.00131 0.00046]
student parameters: 54,915  (6.3x smaller)
epoch   0 lr 1.00e-03 mse 2.492e-01 val rel-L2 [sG 1.43e-01 sM 2.46e-01 a 6.09e-02] ends [7.94e-02 2.02e-01 5.12e-02] 3s
...
epoch 149 lr 1.00e-05 mse 1.349e-05 val rel-L2 [sG 3.50e-03 sM 5.38e-03 a 1.74e-03] ends [1.52e-03 3.00e-03 1.01e-03] 332s
done. student val rel-L2 [0.0035  0.00538 0.00174] (teacher [0.00109 0.00182 0.00064]); 6.3x fewer parameters
```

`ends` 是只看段两端的误差，闭合用到的正是这些点。学生在三个核上的验证误差是 0.0035、0.0054、0.0017，大约是教师的三倍，换来的是查核速度。

输出在 `~/stackem_work/outputs/base3/skn_distill/`：`skn_student.npz`、`train_log.csv`、`distill_curves.pdf` 和 `.png`、`distill_summary.json`。

这一步必须有 PyTorch。没有安装 PyTorch 时它会报 `PyTorch is required for the distillation` 并记为失败。

## 5. 重新训练以后，结果与参考有什么不同

### 5.1 为什么会不同

`reference_results/` 是用 `weights/` 里那三个网络算出来的。你自己训练出来的网络是另外三个网络。虽然随机种子固定，但显卡上的浮点运算顺序在不同的硬件、驱动和库版本下并不相同，训练三百轮之后权重会有细微的差别。所以：

1. 凡是只由参考求解器、HotSpot 和供电网求解决定的数字，应当与参考结果一致。这包括全部真值：每条轨的成核时间、十年内成核的轨数、签核轨宽、温度场、E6 的全部扫描、E3 的七种假设。
2. 凡是经过网络的数字，会在小范围内变动。这包括 E1 的核误差、E2 和 E8 的成核时间误差、StackEM 预测的最早成核时间、E7 里 StackEM 一行的排序指标、E5 的导数和优化轨迹、IBM 基准的误差、训练摘要里的验证误差。

### 5.2 用宽松模式比对

```bash
cd ~/StackEM_clean
python tools/check_results.py --retrained
```

加上 `--retrained` 以后，参考求解器一类的数字仍按严格规则比较，网络一类的数字改用宽松规则。

| 数字的类型 | 不加 `--retrained` | 加 `--retrained` |
|---|---|---|
| 参考求解器一类的整数 | 必须相等 | 必须相等 |
| 参考求解器一类的小数 | 相对偏差不超过 0.001 | 相同 |
| 网络一类的小数 | 相对 0.02 加绝对 0.0002 | 与参考值同号且相差不超过三倍，或者绝对差不超过 0.02 |
| 网络一类的整数 | 必须相等 | 相差不超过 2 和参考值的百分之十中较大的那个 |

宽松规则的含义是：误差指标只要求量级相同。例如参考的误差中位数是 0.26 %，你得到 0.2 % 或 0.5 % 都算通过。输出的读法与 03 号文档第 7 节相同。

如果在路线 B 之后不加 `--retrained` 直接比对，网络一类的文件大多会显示 `DIFF`，这是预期之中的，并不表示出了问题。

### 5.3 怎样判断自己的网络训练得够好

比对通过只说明量级一致。想进一步确认，可以看下面三处，并与参考值对照。

| 看什么 | 文件 | 参考值 |
|---|---|---|
| 教师网络最好的验证误差 | `base3/skn/train_summary.json` 的 `best_val_worst_rel_l2` | 0.0018 |
| 学生网络的验证误差 | `base3/skn_distill/distill_summary.json` 的 `student.val_rel_l2` | 0.0035、0.0054、0.0017 |
| base3 上成核时间误差的中位数 | `base3/e2/e2_summary.json` 的 `full.metrics.<芯片>.tnuc_rel_median` | D1 0.26 %，D2 0.14 %，D3 1.72 % |

查看一个 JSON 文件里的某个值，可以用这样的命令：

```bash
python -c "import json; print(json.load(open('$HOME/stackem_work/outputs/base3/skn/train_summary.json'))['best_val_worst_rel_l2'])"
```

## 6. 手动运行单个阶段

`run_all.sh` 里的每一步都是一条普通的 Python 命令。下面逐条列出，参数与 `run_all.sh` 在正式模式下使用的完全相同。想单独重跑某一步，推荐的做法仍然是 `STACKEM_ONLY=<步骤名> bash scripts/run_all.sh`，因为它会自动记录日志和耗时。手动命令适合想看清楚每一步到底在调用什么，或者想临时改某个参数的读者。

先设置三个简写，后面的命令都用到它们。每开一个新终端都要重新设置。

```bash
source ~/stackem_work/venv/bin/activate
cd ~/StackEM_clean
ROOT=$HOME/stackem_work/outputs
HS=$HOME/stackem_work/HotSpot
A="--config configs/base3.json --root $ROOT --hotspot $HS"
```

`ROOT` 是输出根目录，`HS` 是 HotSpot 目录，`A` 是主算例的三个公共参数。每个实验入口都接受这三个参数：`--config` 指定配置文件，`--root` 指定输出根目录，`--hotspot` 指定 HotSpot 目录。

### 6.1 数据与网络

```bash
python -m unittest stackem.tests.test_core
python -m stackem.experiments.gen_kernels $A --n-profiles 120000
python -m stackem.experiments.train_or_fallback $A --epochs 300 --w-pde 0
python -m stackem.train_distill --data $ROOT/base3/kernels/kernels_train.npz --teacher $ROOT/base3/skn/skn_best.npz --out $ROOT/base3/skn_distill
```

四条依次是单元测试、生成核数据集、训练教师、蒸馏学生。蒸馏命令没有写结构和轮数，因为 `train_distill` 的默认值就是最终采用的设置。

只生成两个留出集而不生成训练集，用的是：

```bash
python -m stackem.experiments.gen_kernels $A --val-only
```

### 6.2 主算例的实验

```bash
python -m stackem.experiments.e1_skn_eval       $A
python -m stackem.experiments.signoff_size      $A
python -m stackem.experiments.e0_validate       $A
python -m stackem.experiments.e2_rail_accuracy  $A
python -m stackem.experiments.e3_decomposition  $A
python -m stackem.experiments.e7_ranking        $A
python -m stackem.experiments.e4_scaling        $A --teacher $ROOT/base3/skn/skn_best.npz --ablate-modes --sizes 82,246,1000,5000,20000
python -m stackem.experiments.e5_sensitivity    $A
python -m stackem.experiments.e6_sweeps         $A
python -m stackem.experiments.e8_ev6            $A
```

E4 的三个额外参数的含义：`--teacher` 让它顺便给教师网络计时，`--ablate-modes` 让它对配置里的网络同时测直接查核和制表查核两种方式，`--sizes` 是要测的轨数。

### 6.3 另外两个堆叠

这两个算例没有自己的网络，用 `--weights` 指向 base3 的学生网络。

```bash
W=$ROOT/base3/skn_distill/skn_student.npz
for E in signoff_size e2_rail_accuracy e3_decomposition e7_ranking; do
  python -m stackem.experiments.$E --config configs/quad4.json --root $ROOT --hotspot $HS --weights $W
done
for E in signoff_size e2_rail_accuracy e3_decomposition e7_ranking; do
  python -m stackem.experiments.$E --config configs/dense3.json --root $ROOT --hotspot $HS --weights $W
done
```

`for ... do ... done` 是让同一条命令对四个实验各执行一次的写法，可以整段粘贴。

### 6.4 教师引擎对照

```bash
T="--config configs/base3_teacher.json --root $ROOT --hotspot $HS"
python -m stackem.experiments.e1_skn_eval       $T
python -m stackem.experiments.e2_rail_accuracy  $T
python -m stackem.experiments.e4_scaling        $T --sizes 82,246,1000,5000,20000 --single-core-max 1000
python -m stackem.experiments.e5_sensitivity    $T
python -m stackem.experiments.e8_ev6            $T
python tools/compare_engines.py --root $ROOT --student base3 --teacher base3_teacher
```

`configs/base3_teacher.json` 里写着 `"base_case": "base3"`，意思是签核轨宽、核数据和权重都从 `base3` 文件夹读取，结果写到 `base3_teacher` 文件夹。`--single-core-max 1000` 表示单核参考求解器只测到 1000 条轨。

### 6.5 方程残差项消融

```bash
python -m stackem.experiments.train_or_fallback $T --out-name ablation_pde --epochs 300 --w-pde 0.05 --out-subdir skn_pde
WP=$ROOT/ablation_pde/skn_pde/skn_best.npz
python -m stackem.experiments.e1_skn_eval       $T --out-name ablation_pde --weights $WP
python -m stackem.experiments.e2_rail_accuracy  $T --out-name ablation_pde --weights $WP
```

`--out-name ablation_pde` 让结果写到 `ablation_pde` 文件夹，`--out-subdir skn_pde` 让权重写到其中的 `skn_pde` 子文件夹，这样不会覆盖教师网络。

### 6.6 IBM 基准、COMSOL 导出、表和图

```bash
python tools/run_ibmpg.py --spice $HOME/stackem_work/ibmpg/ibmpg1.spice --config configs/base3.json --root $ROOT --hotspot $HS --weights $W --unit auto --size-to-jmax 1e6 --max-rails 0 --min-segments 3

python comsol/export_rails.py --e2 $ROOT/base3/e2 --out $ROOT/comsol
python comsol/compare_rails.py --dir $ROOT/comsol
```

## 7. 修改设置

### 7.1 用环境变量改

`run_all.sh` 提供了几个环境变量，写在命令前面即可。

| 变量 | 作用 | 默认值 |
|---|---|---|
| `STACKEM_NPROFILES` | 核训练集的剖面数 | 120000 |
| `STACKEM_EPOCHS` | 教师网络的训练轮数，消融网络也用这个值 | 300 |
| `STACKEM_E4_SIZES` | E4 测速的轨数列表，逗号分隔 | `82,246,1000,5000,20000` |
| `STACKEM_ROOT` | 输出根目录 | `~/stackem_work/outputs` |
| `STACKEM_WORK` | 工作目录 | `~/stackem_work` |
| `STACKEM_HOTSPOT` | HotSpot 目录 | `<工作目录>/HotSpot` |
| `STACKEM_IBMPG_DIR` | 存放 IBM 网表的目录 | `<工作目录>/ibmpg` |
| `STACKEM_IBMPG` | 明确指定要跑的网表，空格分隔的完整路径 | 空，表示扫描上面的目录 |
| `STACKEM_PYTHON` | 用哪个 Python | `python` |
| `STACKEM_NO_LOG=1` | 不写日志文件 | 不设置 |

学生网络的轮数和结构没有对应的环境变量，要改就按第 6.1 节手动运行 `train_distill`，加上 `--epochs`、`--hidden` 等参数。

改了设置以后，结果就与参考结果不可比了。请务必同时换一个输出根目录，避免与正式结果混在一起。例如用六分之一的数据和六分之一的轮数做一次快速试验：

```bash
STACKEM_ROOT=$HOME/stackem_work/outputs_small STACKEM_NPROFILES=20000 STACKEM_EPOCHS=50 bash scripts/run_all.sh
```

比对时相应地指定目录：

```bash
python tools/check_results.py --root ~/stackem_work/outputs_small --retrained
```

这样的试验里参考求解器一类的数字仍然应当通过，网络一类的数字可能因为网络精度下降而超出宽松容差。

### 7.2 改算例

算例的全部物理参数在 `configs/` 的 JSON 文件里。`base3.json` 列出了每一个值，其他几个文件只列出与它不同的键。想试自己的堆叠时，请复制一份配置，改一个新的 `"name"`，不要直接修改原文件：

```bash
cp configs/base3.json configs/mycase.json
```

用文本编辑器把 `mycase.json` 里的 `"name": "base3"` 改成 `"name": "mycase"`，再改你想改的参数，例如顶层芯片的功耗 `"P": 20.0`。然后按第 6.3 节的方式，依次运行签核定线宽和各个实验，把 `--config` 指向新文件，并用 `--weights` 指向 base3 的学生网络。结果会写到 `<输出>/mycase/`。几个 `--config` 文件可以用逗号连起来，后面的覆盖前面的，冒烟测试就是用 `configs/quad4.json,configs/smoke.json` 这种方式缩小规模的。

终端里编辑文件可以用 `nano configs/mycase.json`，改完按 `Ctrl+O` 回车保存，`Ctrl+X` 退出。

### 7.3 代码注释里的“originally”是什么意思

代码里有几处默认值旁边带着这样的注释：

```python
ap.add_argument("--epochs", type=int, default=150)        # originally 60; the final experiments used 150 (see docs)
```

它的意思是：现在的默认值就是产生发布结果时实际使用的值。注释里 `originally` 后面的那个值是这个参数最初的默认值，现在的流程不再使用它，写在那里只是为了说明这个默认值是有意设定的。你不需要做任何事，更不要把它改回去。全部这类注释如下。

| 位置 | 参数 | 现在的默认值，即最终采用的值 | 注释里的原值 |
|---|---|---|---|
| `stackem/train_distill.py` | `--hidden`，学生网络的结构 | `128,128,128,128` | `64,64,64,64` |
| `stackem/train_distill.py` | `--epochs`，蒸馏轮数 | 150 | 60 |
| `stackem/train_distill.py` | `--patience`，提前停止的轮数 | 30 | 15 |
| `stackem/config.py` | `times.n`，输出时刻的个数 | 32 | 64 |
| `stackem/config.py` | `closure.mode`，查核方式 | `tabulated`，制表，192 个点 | `direct`，直接查核 |
| `stackem/config.py` | `skn.weights`，默认使用的网络 | `skn_distill/skn_student.npz`，学生 | `skn/skn_best.npz`，教师 |
| `stackem/experiments/e4_scaling.py` | `--single-core-max`，单核参考求解器测到多少条轨 | 20000 | 1000 |
| `tools/run_ibmpg.py` | `--max-rails`，每个网表取多少条轨 | 0，表示全部 | 400 |
| `tools/run_ibmpg.py` | `--size-to-jmax`，把每条轨的宽度定到多大的电流密度上限 | 1e6 A/cm² | 不定宽 |

教师引擎对照是一个例外：它的配置文件 `configs/base3_teacher.json` 把输出时刻设回 64、查核方式设回直接查核、网络设回教师，`run_all.sh` 给它的 E4 传入 `--single-core-max 1000`。这些正是教师引擎那组参考结果采用的设置。

## 8. 方程残差项消融

### 8.1 它在比较什么

训练网络时可以在损失里加一项，要求网络的输出满足应力方程本身，这一项称为方程残差项。本项目最终采用的教师网络没有用这一项，只用参考求解器的数据训练。消融实验训练一个加了这一项的网络，权重为 0.05，其余设置完全相同，然后比较两者。

这一组有三个步骤。

| 步骤 | 做什么 | 输出 |
|---|---|---|
| `ablation.train` | 用 `--w-pde 0.05` 训练一个 6 层每层 256 的网络 | `ablation_pde/skn_pde/` |
| `ablation.e1` | 这个网络的核精度 | `ablation_pde/e1/` |
| `ablation.e2` | 用这个网络做 base3 的逐轨精度，引擎设置与教师引擎相同 | `ablation_pde/e2/` |

对照的一方是教师引擎的结果 `base3_teacher/e1` 和 `base3_teacher/e2`。

### 8.2 参考机上的结果

| 指标 | 不加残差项，即采用的教师 | 加残差项 |
|---|---|---|
| 300 轮的训练时间 | 1345 秒 | 11080 秒 |
| 最好的验证误差，三个核里最差的一个 | 0.0018 | 0.0029 |
| E1 里 `s_G` 核误差的中位数 | 0.22 % | 0.25 % |
| E1 里 `s_M` 核误差的中位数 | 0.69 % | 1.96 % |
| E2 成核时间误差中位数，D1 | 0.23 % | 0.23 % |
| E2 成核时间误差中位数，D2 | 0.19 % | 0.08 % |
| E2 成核时间误差中位数，D3 | 2.27 % | 0.53 % |

怎样读这张表：加上残差项以后训练时间是原来的 8.2 倍，核本身的验证误差和 E1 误差变大。base3 这一个堆叠上的轨级成核时间误差没有变差，D3 上还更小。本项目据此选择了不加残差项的训练方式，理由是训练代价和核精度。这个结论只在一个堆叠、一次训练上得到，没有用多个随机种子重复。

训练过程的屏幕输出与教师训练相同，只是 `pde` 一列不再是 0，并且每轮慢得多。

## 9. 教师引擎对照

### 9.1 它在比较什么

主流程用的是学生引擎。教师引擎对照回答的问题是：换成小网络、制表查核、更少的输出时刻以后，精度损失了多少，速度提高了多少。两种引擎在同一个堆叠 base3、同一组签核轨宽、同一个参考求解器真值上比较。

| | 教师引擎 | 学生引擎 |
|---|---|---|
| 网络 | 6 层每层 256，343811 个参数 | 4 层每层 128，54915 个参数 |
| 查核方式 | 直接查核 | 制表，每段端点 192 个点 |
| 输出时刻数 | 64 | 32 |
| 配置文件 | `configs/base3_teacher.json` | `configs/base3.json` |
| 结果文件夹 | `base3_teacher` | `base3` |

### 9.2 参考机上的结果

`teacher.compare` 这一步生成的对比表在 `base3_teacher/comparison/comparison_teacher_student.md`，下面摘出主要几行。

| 指标 | 教师引擎 | 学生引擎 |
|---|---|---|
| E2 成核时间误差中位数，D1 | 0.23 % | 0.26 % |
| E2 成核时间误差中位数，D2 | 0.19 % | 0.14 % |
| E2 成核时间误差中位数，D3 | 2.27 % | 1.72 % |
| E2 里 246 条轨的闭合时间，numpy，处理器 | 251.4 秒 | 13.5 秒 |
| E4 里两万条轨的闭合时间，显卡 | 448.4 秒 | 23.4 秒 |
| E5 功耗重新分配后的最早成核时间，真值 | 5.192 年 | 5.204 年 |
| E8 成核时间误差中位数 | 0.64 % | 1.43 % |

怎样读这张表：学生引擎在 base3 的轨级精度上与教师引擎相当，在 E8 的 ev6 布图上误差大一些，闭合速度约为教师引擎的 19 倍。同一目录下的 `compare_timing` 图把两种引擎的 E4 曲线画在一起，`compare_accuracy` 图是每颗芯片上两种引擎的误差。

教师引擎这一组只跑 E1、E2、E4、E5、E8。`reference_results/` 里的那份对比表在教师引擎一栏还填有 E3 和 E7 的数值，现在的流程不为教师引擎运行这两个实验，所以你新生成的表里这两行的教师一栏是短横线，这不是错误。
