# 02 安装

前提：已经按 [01_准备电脑与软件.md](01_准备电脑与软件.md) 做完，仓库在 `~/StackEM_clean`，会打开终端。

本文做三件事：运行安装脚本并逐段解释，检查安装是否正确，跑一次冒烟测试。最后一节列出可能遇到的问题和处理办法。

## 1. 安装脚本做什么

整个安装由一个脚本 `scripts/setup_env.sh` 完成。它依次做五件事，并在屏幕上用 `== 1/5 ... ==` 这样的标题标出当前进行到哪一步。

| 阶段 | 做什么 | 结果放在哪里 |
|---|---|---|
| 1/5 system packages | 用 `apt-get` 安装编译器、Python 的基础组件、解压工具、wget 和 tmux | 系统目录 |
| 2/5 python environment | 新建一个 Python 虚拟环境，装入固定版本的 numpy、scipy、matplotlib、scikit-learn、pandas | `~/stackem_work/venv` |
| 3/5 PyTorch | 安装 PyTorch 2.14.0。检测到 `nvidia-smi` 时装带显卡支持的版本，否则装只用处理器的版本 | 同上 |
| 4/5 HotSpot | 把 `third_party/HotSpot-master.zip` 解压并编译，再跑一个一秒钟的例子确认它能用 | `~/stackem_work/HotSpot` |
| 5/5 unit tests | 运行代码包的单元测试 | 只在屏幕上显示结果 |

虚拟环境是一个独立的文件夹，里面有一套专属于本项目的 Python 和软件包，不会影响系统里的其他 Python，也不受它们影响。

HotSpot 是弗吉尼亚大学的开源芯片热仿真器，StackEM 用它计算堆叠的温度场。

## 2. 先准备 Python 3.11

参考结果是用 Python 3.11.16 产生的。Ubuntu 24.04 自带的是 Python 3.12，所以建议先装一个 3.11。安装脚本的规则是：系统里有 `python3.11` 这个命令就用它，没有就用 `python3` 并给出警告。

在终端里输入下面四行。它们添加一个提供各版本 Python 的软件源，然后安装 3.11。

```bash
sudo apt-get update
sudo apt-get install -y software-properties-common
sudo add-apt-repository -y ppa:deadsnakes/ppa
sudo apt-get install -y python3.11 python3.11-venv python3.11-dev
```

检查：

```bash
python3.11 --version
```

应当显示 `Python 3.11.` 开头的一行，最后一位数字是多少都可以。

如果这个软件源在你的网络环境下连不上，有两种退路。

1. 用其他途径得到一个 Python 3.11 的可执行文件，运行安装脚本时用 `STACKEM_PYTHON_BIN=<该文件的完整路径>` 告诉它。
2. 直接用系统自带的 Python。这时固定版本的软件包可能没有对应的安装包，需要加 `STACKEM_UNPINNED=1` 改装最新版本，见第 8.2 节。这样能运行，但发布结果没有在这种组合下产生过，数值是否完全一致没有验证。

如果你的电脑上装过 conda，提示符前面带有 `(base)` 字样，请先输入 `conda deactivate` 再继续，否则虚拟环境会建在 conda 的 Python 之上。

## 3. 运行安装脚本

1. 进入仓库目录。

   ```bash
   cd ~/StackEM_clean
   ```

2. 运行脚本，同时把屏幕输出存进 `setup_env.log`，以后出问题可以翻看。

   ```bash
   bash scripts/setup_env.sh 2>&1 | tee setup_env.log
   ```

   开头会要求输入一次密码，因为安装系统软件需要管理员权限。整个过程约 10 分钟，主要花在下载上。带显卡支持的 PyTorch 连同它的依赖有好几 GB，网速慢时会更久。

3. 等到屏幕出现 `== done ==`。

下面逐段说明屏幕上应当出现什么。

### 3.1 第 1 段：系统软件

```text
== 1/5 system packages ==
```

之后是 `apt-get` 的大量输出，最后几行类似 `Setting up ...`。这一段安装 `build-essential python3 python3-venv python3-dev unzip bzip2 wget tmux`。其中 `build-essential` 包含 gcc 编译器和 make，用来编译 HotSpot。

### 3.2 第 2 段：Python 环境

```text
== 2/5 python environment ==
   interpreter: python3.11 (Python 3.11.x)
```

`interpreter` 一行告诉你它选中了哪个 Python。如果这里显示的不是 3.11，会多出一行以 `[warn] not Python 3.11` 开头的警告。接着是 pip 下载和安装软件包的输出，最后一行以 `Successfully installed` 开头，后面列出 `numpy-2.4.6`、`scipy-1.17.1` 等名字。

### 3.3 第 3 段：PyTorch

```text
== 3/5 PyTorch ==
```

接着是下载 PyTorch 的输出。这一段结束时脚本会打印两行版本汇总，这是检查安装是否正确的最重要的两行：

```text
   python 3.11.x | numpy 2.4.6 | scipy 1.17.1 | matplotlib 3.11.2 | scikit-learn 1.9.1 | pandas 3.0.6
   torch 2.14.0+cu130 | cuda available: True
```

有显卡时第二行应当是 `2.14.0+cu130` 和 `cuda available: True`。没有显卡时是 `2.14.0+cpu` 和 `cuda available: False`，这也是正常的。

### 3.4 第 4 段：HotSpot

```text
== 4/5 HotSpot (built from third_party/HotSpot-master.zip) ==
   HotSpot built: /home/<你的用户名>/stackem_work/HotSpot/hotspot
   sha256 <一串 64 位的十六进制字符>
   (released results: 4b4954cd8eff2201955be7c16de5e99b1294d9427153bf6371e075924f9438fc; equal only for the same compiler version)
   HotSpot example1 runs
```

编译用不了一分钟，过程中的输出写在 `~/stackem_work/HotSpot/make.log` 里，屏幕上只显示结果。`sha256` 是可执行文件的指纹。如果你的 gcc 版本与参考机相同，也就是 13.3.0，这一串字符会与括号里的那一串完全相同。不相同也不是错误，只说明编译器版本不同。`HotSpot example1 runs` 表示 HotSpot 自带的例子能算出温度文件。

### 3.5 第 5 段：单元测试

```text
== 5/5 unit tests ==
......................
----------------------------------------------------------------------
Ran 22 tests in 3.7s

OK

== done ==
Activate the environment in every new terminal:   source /home/<你的用户名>/stackem_work/venv/bin/activate
Then, from the repository root:                    bash scripts/run_smoke.sh
```

关键是 `OK` 和 `== done ==`。点号中间可能夹着几行以 `[parse]` 和 `[dc]` 开头的输出，那是其中一个测试在解析一个小的电源网，属于正常现象。测试的秒数因机器而异。

## 4. 每次打开终端都要做的事

安装脚本自己激活过虚拟环境，但那只在脚本内部有效。以后每次新开一个终端窗口，或者新建一个 tmux 会话，都要先输入下面两行，再运行任何 StackEM 的命令。

```bash
source ~/stackem_work/venv/bin/activate
cd ~/StackEM_clean
```

第一行激活虚拟环境。激活成功后提示符最前面会多出 `(venv)`。第二行进入仓库目录，因为运行测试和单步命令时必须站在仓库根目录。

忘记激活是最常见的错误，表现是运行时报 `ModuleNotFoundError: No module named 'numpy'` 之类的错。

想退出虚拟环境时输入 `deactivate`，或者直接关掉窗口。

## 5. 检查安装

下面四项检查各自独立，都应当通过。先按第 4 节激活环境并进入仓库目录。

### 5.1 Python 与软件包版本

```bash
python --version
python -c "import numpy, scipy, matplotlib, sklearn, pandas; print(numpy.__version__, scipy.__version__, matplotlib.__version__, sklearn.__version__, pandas.__version__)"
```

预期输出：

```text
Python 3.11.x
2.4.6 1.17.1 3.11.2 1.9.1 3.0.6
```

### 5.2 PyTorch 与显卡

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

有显卡时预期 `2.14.0+cu130 True`。再看一下 PyTorch 认到的显卡名称：

```bash
python -c "import torch; print(torch.cuda.get_device_name(0))"
```

预期显示你的显卡型号。没有显卡的机器上第一条显示 `2.14.0+cpu False`，第二条不要运行。

### 5.3 HotSpot

```bash
ls -l ~/stackem_work/HotSpot/hotspot
ls ~/stackem_work/HotSpot/examples/example4/example.config
```

两条都应当列出文件而不报错。第一个是可执行文件。第二个是配置模板，StackEM 每次调用 HotSpot 都以它为底稿，E8 实验还要用到同一目录下的 ev6 布图文件。

### 5.4 单元测试

```bash
cd ~/StackEM_clean
python -m unittest stackem.tests.test_core
```

预期最后几行是 `Ran 22 tests` 和 `OK`，几秒钟完成。

## 6. 冒烟测试

冒烟测试用很小的规模把正式流程的每一步都走一遍，目的只是确认环境、路径和 HotSpot 都能正常工作。它算出来的数字没有物理意义，不要拿去和参考结果比较。

### 6.1 它做什么

`scripts/run_smoke.sh` 调用的就是正式流程的脚本 `scripts/run_all.sh`，只是把模式设成 smoke。步骤的顺序和名字与正式流程完全相同，规模缩小如下。

| 项目 | 正式流程 | 冒烟测试 |
|---|---|---|
| 核训练集的剖面数 | 120000 | 2000 |
| 教师网络 | 6 层每层 256，300 轮 | 4 层每层 128，8 轮 |
| 学生网络 | 4 层每层 128，150 轮 | 2 层每层 32，3 轮 |
| HotSpot 网格 | 64 乘 64 | 32 乘 32 |
| 参考求解器每段的单元数 | 60 | 40 |
| E2 和 E3 每颗芯片的轨数 | 全部 | 8 到 10 条 |
| E4 的规模 | 82 到 20000 条轨 | 24 和 82 条轨 |
| IBM 基准 | 下载的真实网表 | 程序自己生成的一个小网表 |
| 输出目录 | `~/stackem_work/outputs` | `~/stackem_work/outputs_smoke` |

### 6.2 运行

建议在 tmux 里运行。

```bash
tmux new -s smoke
source ~/stackem_work/venv/bin/activate
cd ~/StackEM_clean
bash scripts/run_smoke.sh
```

### 6.3 要多久

脚本注释里记录的实测是：一台 2 核无显卡的机器上 45 到 70 分钟。时间主要花在 E8 的两次 ev6 堆叠热仿真和三次签核定线宽上，前者是单线程的。工作站会快几倍。参考机上没有为冒烟测试单独计时。

### 6.4 成功是什么样子

每一步开始时会打印一行带时间和步骤名的标题，结束时打印 `[done] 步骤名 (秒数)`：

```text
=================== 2026-10-04 10:00:00  tests ===================
...
[done] tests (3s)
```

全部结束后打印一张汇总表，共 43 行步骤，再加一行 `total`。成功的标志是表里每一行的状态都是 `ok`，并且最后出现下面这一行：

```text
StackEM flow finished: /home/<你的用户名>/stackem_work/outputs_smoke (all executed steps succeeded)
```

汇总表的样子如下，`<秒数>` 处是每一步实际用的秒数，因机器而异。

```text
step                     seconds  state
tests                    <秒数>  ok
kernels                  <秒数>  ok
...
figs.index_dense3        <秒数>  ok
total                    <秒数>
step table: /home/<你的用户名>/stackem_work/outputs_smoke/logs/steps_<时间>.tsv
```

冒烟测试里有两处输出看起来像问题，实际是正常的。

1. `comsol.compare` 这一步会打印一行以 `no ... comsol_rails_result.csv` 开头的提示，说明还没有 COMSOL 的求解结果。这一步的状态仍然是 `ok`。
2. 没有安装 PyTorch 的机器上，教师网络改用 scikit-learn 的替代训练器，学生网络直接复制教师网络，E4 和 E5 里需要 PyTorch 的部分由实验自己跳过。

### 6.5 失败怎么办

某一步失败时脚本不会停下，它把这一步记为 `FAILED`，继续跑后面的步骤，最后一行会给出只重跑失败步骤的命令，形如：

```text
re-run them with:  STACKEM_ONLY=e8,teacher.e8 bash scripts/run_all.sh
```

冒烟模式下重跑要用 `run_smoke.sh`，把同样的 `STACKEM_ONLY` 放在前面：

```bash
STACKEM_ONLY=e8,teacher.e8 bash scripts/run_smoke.sh
```

出错的详细信息在日志 `~/stackem_work/outputs_smoke/logs/run_all_<时间>.log` 里。用下面的命令找到最新的日志并搜索出错位置：

```bash
ls -t ~/stackem_work/outputs_smoke/logs/run_all_*.log | head -1
grep -n "Traceback\|FAILED\|Error" $(ls -t ~/stackem_work/outputs_smoke/logs/run_all_*.log | head -1)
```

### 6.6 冒烟测试之后

冒烟测试的输出与正式运行的输出在不同的目录里，互不影响。确认成功后可以删掉它腾出空间：

```bash
rm -rf ~/stackem_work/outputs_smoke
```

接下来选一条路线：[03_复现实验_使用发布的权重.md](03_复现实验_使用发布的权重.md) 或 [04_复现实验_从零开始.md](04_复现实验_从零开始.md)。

## 7. 安装脚本的可选开关

开关写在命令的最前面，可以同时写多个，用空格隔开。例如 `STACKEM_TORCH=cpu STACKEM_NO_APT=1 bash scripts/setup_env.sh`。

| 开关 | 作用 | 默认 |
|---|---|---|
| `STACKEM_WORK=<目录>` | 工作目录的位置 | `~/stackem_work` |
| `STACKEM_PYTHON_BIN=<可执行文件>` | 建虚拟环境用的 Python | 有 `python3.11` 就用它，否则用 `python3` |
| `STACKEM_TORCH=auto` 或 `cuda`、`cpu`、`none` | 装哪种 PyTorch。`none` 表示不装 | `auto`，检测到 `nvidia-smi` 时装显卡版 |
| `STACKEM_NO_APT=1` | 不调用 `apt-get`，用于没有管理员权限或系统软件已经装好的机器 | 不设置 |
| `STACKEM_UNPINNED=1` | 安装最新版本的软件包，不按固定版本 | 不设置 |
| `STACKEM_VENV_ARGS=<参数>` | 传给 `python -m venv` 的额外参数 | 空 |

如果改了 `STACKEM_WORK`，以后运行所有脚本时都要带上同样的 `STACKEM_WORK=<目录>`，激活环境的路径也相应改变。初学者请保持默认。

## 8. 常见安装问题

### 8.1 下载很慢或中途断开

现象是 pip 长时间没有进度，或者报 `ReadTimeoutError`、`Connection reset`。

处理办法：

1. 直接重新运行安装脚本。脚本可以重复运行：虚拟环境已存在就不再新建，已经装好的包不会重装，HotSpot 已编译好就跳过。

   ```bash
   cd ~/StackEM_clean
   bash scripts/setup_env.sh 2>&1 | tee setup_env.log
   ```

2. 给 pip 指定一个离你近的镜像站，并把超时时间放宽。把下面的镜像地址换成你所在地区可用的 PyPI 镜像。

   ```bash
   PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple PIP_DEFAULT_TIMEOUT=600 bash scripts/setup_env.sh 2>&1 | tee setup_env.log
   ```

   这两个变量是 pip 自己认识的环境变量，对脚本里所有的 pip 命令生效。需要说明一点：脚本安装 PyTorch 时先尝试 PyTorch 官方的下载地址，失败后才退回到你指定的镜像。镜像站上的 PyTorch 如果不是 CUDA 13.0 的版本，装完后请按 8.3 节检查。
3. `apt-get` 慢时，可以把 Ubuntu 的软件源换成附近的镜像，做法请参考该镜像站的帮助页，换完后重新运行安装脚本。

### 8.2 Python 版本不对

现象是第 2 段的 `interpreter` 一行显示的不是 3.11，并且紧接着安装固定版本的包时报 `No matching distribution found`。

处理办法：按第 2 节装好 `python3.11`，删掉已经建好的虚拟环境，再重新运行脚本。

```bash
rm -rf ~/stackem_work/venv
bash scripts/setup_env.sh 2>&1 | tee setup_env.log
```

实在装不上 3.11 时，改用不固定版本的方式：

```bash
rm -rf ~/stackem_work/venv
STACKEM_UNPINNED=1 bash scripts/setup_env.sh 2>&1 | tee setup_env.log
```

### 8.3 PyTorch 说显卡不可用

现象是有 NVIDIA 显卡，但 `cuda available:` 显示 `False`。按顺序排查。

1. 在终端里输入 `nvidia-smi`。如果这一步就报错，问题在驱动，回到 01 号文档的 3.4 节。
2. 查看装上的是哪种 PyTorch：

   ```bash
   python -c "import torch; print(torch.__version__)"
   ```

   如果显示 `2.14.0+cpu`，说明安装时没有检测到 `nvidia-smi`。显卡驱动修好以后，强制重装显卡版：

   ```bash
   source ~/stackem_work/venv/bin/activate
   pip uninstall -y torch
   STACKEM_TORCH=cuda bash scripts/setup_env.sh 2>&1 | tee setup_env.log
   ```

3. 如果显示的是带 `+cu` 的版本但仍然不可用，通常是 Windows 的显卡驱动太旧，不支持 CUDA 13.0 的运行库。更新驱动，在 PowerShell 里执行 `wsl --shutdown`，再重新打开 Ubuntu。

显卡始终不可用也可以继续，流程会改用处理器，影响见 01 号文档 1.4 节。

### 8.4 HotSpot 编译失败

现象是第 4 段出现 `HotSpot build failed, see .../make.log`。

1. 先看编译日志的末尾：

   ```bash
   tail -n 30 ~/stackem_work/HotSpot/make.log
   ```

2. 最常见的原因是编译器没装上，日志里会有 `gcc: command not found` 或 `make: command not found`。补装后重跑脚本：

   ```bash
   sudo apt-get install -y build-essential
   bash scripts/setup_env.sh 2>&1 | tee setup_env.log
   ```

3. 如果脚本一开始就提示 `missing command: gcc`、`make` 或 `unzip`，同样用上面的 `apt-get` 命令补装，`unzip` 用 `sudo apt-get install -y unzip`。
4. 想从头重新编译时，删掉 HotSpot 目录再运行脚本，脚本会重新解压和编译：

   ```bash
   rm -rf ~/stackem_work/HotSpot
   bash scripts/setup_env.sh 2>&1 | tee setup_env.log
   ```

5. 出现 `[error] HotSpot quick check failed` 说明编译出了可执行文件但例子没有算出结果。先确认仓库和工作目录都在 Linux 的家目录下，没有放在 `/mnt/c` 上，然后按上一条重新编译。

### 8.5 在错误的目录里运行测试

现象是运行 `python -m unittest stackem.tests.test_core` 时报：

```text
ModuleNotFoundError: No module named 'stackem'
```

原因是当前目录不是仓库根目录。Python 是在当前目录下寻找 `stackem` 这个文件夹的。处理办法：

```bash
cd ~/StackEM_clean
python -m unittest stackem.tests.test_core
```

同样的道理适用于文档里所有以 `python -m stackem...`、`python tools/...`、`python comsol/...` 开头的命令，它们都要在仓库根目录下运行。以 `bash scripts/...` 开头的脚本会自己切换到仓库根目录，在哪里运行都可以。

### 8.6 提示找不到 numpy 或 torch

现象是 `ModuleNotFoundError: No module named 'numpy'`。原因是没有激活虚拟环境，按第 4 节输入 `source ~/stackem_work/venv/bin/activate`。

### 8.7 输入密码后提示不在 sudoers 文件里

说明你的用户没有管理员权限，常见于共用的服务器。请管理员代为安装第 3.1 节列出的系统软件，然后用 `STACKEM_NO_APT=1 bash scripts/setup_env.sh` 运行脚本，它会跳过 `apt-get`。

更多运行阶段的问题见 [09_常见问题.md](09_常见问题.md)。
