# 结果文档总览

`docs/results/` 这组文档说明 `reference_results/` 里的全部内容，一个实验一个文件。`reference_results/` 是用仓库里发布的权重 `weights/` 在参考机器上跑出来的最终结果，目录结构与自己重新运行后的输出根目录 `~/stackem_work/outputs/` 相同，可以逐文件对照。论文只用了其中一部分，这里把论文之外的实验也全部写出。

方法和术语的完整解释在 [../06_思路与方法.md](../06_思路与方法.md)，设计上的取舍在 [../07_设计选择与简化.md](../07_设计选择与简化.md)，怎么安装和运行在 [../02_安装.md](../02_安装.md)、[../03_复现实验_使用发布的权重.md](../03_复现实验_使用发布的权重.md)、[../04_复现实验_从零开始.md](../04_复现实验_从零开始.md)。每个结果文档开头都会把自己用到的术语再解释一遍，可以单独阅读。

## 1. 这组文档怎么读

每个文件的结构相同：

1. 这个实验回答什么问题
2. 原理与做法
3. 怎么运行：`scripts/run_all.sh` 的步骤名、实际执行的命令、参考机器上的耗时
4. 输出文件：目录里每个文件装的是什么
5. 结果：完整的表，每张图及其读法
6. 怎么理解
7. 论文用了哪些，哪些是论文之外的
8. 注意事项：数据里看得到的局限和异常

文档里每一个取自结果文件或日志的数字，都在 `docs/checks/results_<编号>.jsonl` 里有一行核对记录，写明它来自哪个文件的哪个键或哪条表达式。在仓库根目录运行

```bash
python3 tools/verify_docs.py docs/checks/results_05.jsonl
```

会把这些数字重新算一遍并与文档里印的值比较，最后一行应当是 `... 0 failed`。不带参数时核对 `docs/checks/` 下的全部清单。表格由脚本从 json 文件生成，没有手抄的数。

参考机器：Windows 11 上的 WSL2 Ubuntu 24.04，AMD Ryzen 9 9950X 处理器 16 核 32 线程，NVIDIA GeForce RTX 4070 Ti SUPER 16 GB 显卡，Python 3.11.16，PyTorch 2.14.0。文档里的耗时都是这台机器上的。

## 6. `reference_results/` 里不属于某个实验的文件

| 位置 | 内容 |
|---|---|
| `MANIFEST.tsv` | 目录里每个文件一行：路径、字节数、sha256、来源、备注 |
| `base3/figs/framework.png`、`.pdf`、`_data.json`、`_data.npz` | 流程框图，由 `figs.framework` 步骤的 `tools/framework_figure.py` 画出，不读任何结果文件 |
| `<算例>/tables/table_params.md`、`.tex`、`.json` | 参数表，由 `tables.<算例>` 步骤的 `tools/param_table.py` 从配置和定线宽结果生成 |
| `logs/` | 参考运行的日志，见第 7 节 |

![流程框图](../../reference_results/base3/figs/framework.png)

流程框图分三条色带。最上面一条是离线部分，每种工艺只做一次：用参考求解器生成随机剖面的核数据，训练网络，得到冻结的段核函数。中间一条是每个堆叠算例要做的：堆叠定义，HotSpot 三维温度场，电源网格的直流电流，不朽筛查，结点闭合。最下面一条是三类输出：堆叠级签核、定点修复、灵敏度与功耗再分配。箭头表示数据流向，核函数只在段的两个端点被查询。

各目录里反复出现的两类文件：

- `config_used.json`：这次运行实际使用的完整配置，每个实验目录一份。
- `<图名>_data.json` 和 `<图名>_data.npz`：每张图配一对。json 写明图里每条曲线的标签和它对应 npz 里的哪两个数组，npz 存坐标。想重画或换样式时直接读这两个文件，不必重跑实验。

自己运行后输出目录里比参考结果多出来的东西：各实验的 `hotspot/` 草稿目录，逐轨的应力数组 `*_pred.npz`、`*_truth.npz`、`*_stackem.npz`，轨的几何描述 `*_rails.json`，核数据集的三个 npz，以及图索引目录 `figs_index/`。前几类体积大，随发布文件提供；`tools/check_results.py --root ~/stackem_work/outputs` 会把新结果与 `reference_results/` 逐项比较。

读这些日志时要知道三件事。

1. 日志和各 json 的 `_meta.cmd`、`config_used.json` 里的文字是参考运行当时的写法。当时教师引擎和学生引擎的结果分别写在两个输出根目录 `~/stackem_work/outputs_teacher` 和 `~/stackem_work/outputs` 下，步骤标题、HotSpot 目录名、IBM 网表目录名也与现在的 `run_all.sh` 不同，标题里还有 plain、distilled、paper engine 这样的词：plain 指教师引擎，distilled 指学生引擎。现在的流程只有一个输出根目录和一套步骤名，数值结果相同。
2. 日志里有一些运行不在 `reference_results/` 里：`final_1_full.log` 和 `final_2_extras.log` 里教师引擎的 quad4、dense3；`final_4_extras.log` 里只保留 2000 条轨的 ibmpg2、ibmpg3；`ibmpg_full.log` 里 CPU 上的 ibmpg1、两次没跑完的 ibmpg2 和坐标单位取 1e-8 m 的 ibmpg6。日志里指向 `configs/quad4_teacher.json`、`configs/dense3_teacher.json` 的命令行对应的就是前一类，这两个配置文件不在仓库里。
3. COMSOL 一侧没有日志。
