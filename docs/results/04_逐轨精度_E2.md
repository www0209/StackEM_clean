# 实验 E2：逐轨精度，代理解对参考解

本章说明五个目录：`reference_results/base3/e2/`、`quad4/e2/`、`dense3/e2/`、`base3_teacher/e2/`、`ablation_pde/e2/`。核对清单是 `docs/checks/results_04.jsonl`。

## 1. 这个实验回答什么问题

StackEM 的快速路径由两部分组成：网络给出单段导线的三个核函数，结点闭合把一条轨上的各段在结点处拼起来，得到每个结点的应力历史和这条轨的成核时间。E2 要回答的是：把这条快速路径用到整个堆叠的每一条轨上，结果与逐条轨的有限体积参考解相差多少。

它同时检验零样本能力。网络只在随机的单段温度剖面上训练，从没见过任何堆叠。quad4 和 dense3 直接使用 base3 的学生权重，`alone` 和 `uniform` 两个变体还换了温度场。

术语：

- 轨：电源网格里的一整条金属带，从芯片一边到另一边，被馈电点切成若干段。base3 每层芯片有 41 条横向轨和 41 条纵向轨。
- 会成核的轨，图和文件里写作 mortal：在时间窗内成核时间有限的轨。时间窗的上限是 $10^{9.5}$ 秒，约 100 年。
- 不朽的轨，文件里写作 immortal：稳态最大应力低于临界应力，永远不成核，成核时间记为无穷大。
- 参考解，文件里写作 truth：对每条轨建一棵有限体积树，每段 60 个单元。
- 代理解，文件里写作 pred：网络加结点闭合。
- Kendall tau：衡量两个排序一致程度的系数，1 表示完全同序。
- 合并统计，图和论文里写作 pooled：把一个堆叠里所有芯片的轨合在一起统计。

## 2. 原理与做法

### 2.1 脚本流程

`stackem/experiments/e2_rail_accuracy.py` 的步骤：

1. 读配置和定线宽结果，载入网络权重。
2. 运行 HotSpot，得到堆叠里每层芯片的温度场和每层芯片单独封装时的温度场，再对每层芯片的电源网格做直流求解，得到每段的电流密度。
3. 对三个变体依次做两次求解，先代理解再参考解，分别计时。
4. 计算逐芯片指标和堆叠级摘要，画图，保存逐轨数据。

### 2.2 三个变体

变体只在给轨赋温度的方式上不同。

| 变体 | 温度来源 | 含义 |
|---|---|---|
| `full` | 堆叠的三维温度场 | 完整物理 |
| `alone` | 芯片单独封装时的温度场，单面散热 | 芯片级签核看到的温度 |
| `uniform` | 整层芯片取堆叠中该芯片的平均温度 | 只提供一个平均温度的做法 |

在 E2 里这三个变体用来换输入分布，检验代理解在不同温度场下是否都准确。它们的物理含义在 [05_物理分解与排序_E3_E7.md](05_物理分解与排序_E3_E7.md) 里讨论。

### 2.3 成核时间怎么求

参考解的成核时间取自有限体积求解器内部的细时间步历史，在相邻两个内部时间步之间线性插值。代理解的成核时间在 M 个输出时刻上找第一次越过临界应力的区间，再按 $\sqrt t$ 线性插值。

### 2.4 逐芯片指标

记某层芯片上代理解的成核时间为 tp，参考解为 tt。

| 字段 | 定义 |
|---|---|
| `n` | 该芯片参与比较的轨数 |
| `n_mortal` | 两种解法都给出有限成核时间的轨数 |
| `tnuc_rel_median`、`tnuc_rel_p90`、`tnuc_rel_max` | 在上面这些轨上算 `abs(tp - tt) / tt`，再取中位数、90 % 分位数、最大值 |
| `sigma_relL2_median`、`sigma_relL2_p90` | 对每条轨，把全部输出时刻、全部结点的应力排成一个向量，算相对二范数误差，再在轨之间取中位数和 90 % 分位数。只统计没被筛成不朽的轨 |
| `mortality_agreement` | 两种解法对是否成核判断一致的轨所占比例 |
| `top10_hit` | 按参考解取成核最早的 10 条轨，按代理解也取 10 条，交集大小除以 10 |
| `kendall_top50` | 取参考解最早的 50 条轨，算两种解法排序的 Kendall tau |

堆叠级摘要 `stack_pred` 和 `stack_truth`：`earliest_t_nuc_years` 是所有芯片里最早的成核时间，`critical_die` 是它所在的芯片，`n_mortal_10yr` 和 `n_mortal_100yr` 是成核时间不超过 10 年和 100 年的轨数。一年按 365.25 天即 31557600 秒换算。

### 2.5 合并统计的算法

`e2_summary.json` 只存逐芯片的指标。论文引用的是把所有芯片合在一起的统计，图右下角标注的 n、median、p90 也是合并统计，由绘图代码现算。本章的合并数字按下面的步骤从逐轨文件重算。

1. 读 `e2_<变体>_pred.json` 和 `e2_<变体>_truth.json` 的 `rails` 列表。两个列表顺序相同，每个元素是一条轨，其中 `t_nuc_s` 是以秒计的成核时间，不成核时为无穷大。
2. 保留两边 `t_nuc_s` 都有限的轨，个数记为 n。
3. 对每条保留的轨算带符号的相对误差 `(pred - truth) / truth`。
4. 中位数取绝对值的中位数，p90 取绝对值的 90 % 分位数，最大值取绝对值的最大值，带符号中位数取第 3 步的中位数。
5. “10 年内”的统计在第 2 步上再加条件 `truth <= 10 * 31557600` 秒。

用 Python 写出来就是：

```python
import json, math, statistics
J = lambda p: json.load(open(p))            # 文件里的 Infinity，Python 的 json 模块可以直接读
P = J("reference_results/base3/e2/e2_full_pred.json")["rails"]
T = J("reference_results/base3/e2/e2_full_truth.json")["rails"]
r = [(float(p["t_nuc_s"]) - float(t["t_nuc_s"])) / float(t["t_nuc_s"])
     for p, t in zip(P, T)
     if math.isfinite(float(p["t_nuc_s"])) and math.isfinite(float(t["t_nuc_s"]))]
a = sorted(abs(x) for x in r)
print(len(r), statistics.median(a))          # n 和中位数
k = (len(a) - 1) * 0.9; f = int(k)           # 线性插值的 90 % 分位数，与 numpy.percentile 相同
print(a[f] + (a[min(f + 1, len(a) - 1)] - a[f]) * (k - f))
```

核对清单里每个合并数字都是一条这样的表达式。

## 3. 怎么运行

| 步骤 | 命令 | 输出 |
|---|---|---|
| `e2` | `python -m stackem.experiments.e2_rail_accuracy --config configs/base3.json --root <根> --hotspot <HotSpot>` | `base3/e2/` |
| `quad4.e2` | 同上，配置 `configs/quad4.json`，加 `--weights <根>/base3/skn_distill/skn_student.npz` | `quad4/e2/` |
| `dense3.e2` | 同上，配置 `configs/dense3.json`，加同样的 `--weights` | `dense3/e2/` |

| `ablation.e2` | 配置 `configs/base3_teacher.json`，加 `--out-name ablation_pde --weights <根>/ablation_pde/skn_pde/skn_best.npz` | `ablation_pde/e2/` |

```bash
STACKEM_ONLY=e2,quad4.e2,dense3.e2,teacher.e2,ablation.e2 bash scripts/run_all.sh
```

## 4. 输出文件

每个 `e2/` 目录 20 个文件。

| 文件 | 内容 |
|---|---|
| `e2_summary.json` | 全部指标：`provider`；`pg` 是每层芯片的电流密度与压降统计；三个变体各自的 `metrics`、`seconds_closure`、`seconds_truth`、`stack_pred`、`stack_truth`；`_meta` |
| `config_used.json` | 这次运行的完整配置 |
| `e2_full_pred.json`、`e2_alone_pred.json`、`e2_uniform_pred.json` | 代理解的逐轨数据。`summary` 与 `stack_pred` 相同；`rails` 是每条轨一条记录：`die`、`kind` 即 H 或 V、`index`、`t_nuc_s`、成核结点及其坐标、稳态最大应力 `sigma_ss_max`、是否不朽 `immortal`、最大电流密度 `j_max`、最高温度 `T_max`、平均残余应力、裕量 `margin_h` |
| `e2_full_truth.json`、`e2_alone_truth.json`、`e2_uniform_truth.json` | 参考解的逐轨数据，结构同上 |
| `e2_parity_full`、`e2_parity_alone`、`e2_parity_uniform` 的 `.png`、`.pdf` | 对角图 |
| 三张图的 `_data.json`、`_data.npz` | 图里每个点的坐标 |

自己运行时还会写出逐轨的应力数组 `e2_<变体>_pred.npz`、`_truth.npz` 和轨的几何描述 `_rails.json`，以及 `hotspot/` 草稿目录。这些文件体积大，不在仓库里。

## 6. 怎么理解

1. 在主算例 base3 上，学生引擎对 128 条会成核的轨的成核时间中位误差是 0.15 %，90 % 的轨在 0.90 % 以内，10 年内违例的 26 条轨一条不多一条不少。堆叠最早成核时间代理解 2.405 年对参考解 2.389 年，相差 0.66 %。
2. 零样本迁移成立。quad4 的芯片数、尺寸、功耗、热阻都与 base3 不同，中位误差仍在千分之几。
3. 签核真正关心的是 10 年内的轨。在这个范围内，三个堆叠的中位误差都不超过 0.4 %。
4. 误差最大的总是顶层的热芯片，base3 和 dense3 的 D3，quad4 的 D4。它们线宽大、电流密度低、成核晚，热迁移的贡献相对最大，而 $s_M$ 是网络拟合得最差的核函数。
5. 应力的误差比成核时间的误差小。成核时间是应力曲线与临界应力的交点，曲线越平，同样的应力误差换算成的时间误差越大。dense3 `alone` 的离群点是这一点的极端情形。
6. 5.0 节的表里，base3 上三个网络的合并中位误差从小到大依次是消融网络、学生引擎、教师引擎，三者都在千分之几以内。学生引擎并不比教师引擎差，它的闭合耗时不到教师引擎的十八分之一。

## 8. 注意事项

1. dense3 的 `alone` 变体在 D1 的 H76、V76 两条轨上代理解误差超过 100 %，并使该变体最先失效的芯片判错，见 5.3 节。`alone` 变体不参与堆叠签核的结论，但 E7 里“芯片级签核”那一行的参考数字用的是参考解，不受影响。
2. dense3 的 `full` 变体有系统性的负偏，代理解整体偏早约 1.8 %。偏早意味着偏保守。原因没有查明；dense3 的轨有 80 段，是 base3 的两倍，闭合里误差的累积可能更明显。
3. quad4 多报一条边界轨，另有几条轨在时间窗末端被代理解判为成核，见 5.2 节。
4. 教师引擎的参考解与学生引擎的参考解不是逐位相同。例如 base3 `alone` 的最早成核时间，5.1 节是 20.3551 年，5.4 节是 20.3568 年。两种引擎的输出时刻数不同，参考求解器的内部时间步要落在输出时刻上，结果在万分之一量级上有差别，不影响任何计数。
5. 教师引擎在 `full` 变体的 D2 上有一个 4.7 % 的离群点，学生引擎没有。教师并不是在每条轨上都比学生准。
6. 误差统计只包含两种解法都成核的轨。只在一种解法里成核的轨不进入误差统计，只体现在成核判断一致率里。
7. 误差统计不设时间权重。一条 90 年才成核的轨与一条 3 年成核的轨权重相同。
8. D3 和 D4 每个变体只有 8 条轨成核，它们的 p90 与最大值几乎相等，统计意义有限。
9. 一层芯片会成核的轨少于 50 条时，`kendall_top50` 的排序里会混入成核时间为无穷的轨，它们成为并列值。
10. 合并统计没有存进任何摘要文件，只能从逐轨文件重算，或从图上读。论文引用的正是这组数字。
11. 对角图下半幅的纵轴范围有上限，超出的点不显示。
12. `base3_teacher` 和 `ablation_pde` 两个目录的 `_meta.cmd` 与 `config_used.json` 记录的是参考运行当时的写法，见 [00_总览.md](00_总览.md)。
