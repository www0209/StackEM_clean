# 03 复现实验：使用发布的权重

这是路线 A。它用仓库 `weights/` 里已经训练好的三个网络，把全部实验重新算一遍，不生成核训练集，也不做任何训练。`weights/` 里的网络就是产生 `reference_results/` 的那三个网络，所以这条路线算出来的结果应当与参考结果在数值上吻合。

前提：已经按 [02_安装.md](02_安装.md) 装好环境并通过冒烟测试。

文中的耗时都取自参考机的日志 `reference_results/logs/`，逐条核对清单是 `docs/checks/03_复现实验_使用发布的权重.jsonl`。

## 1. 先认识几个名字

| 名字 | 含义 |
|---|---|
| 教师网络 | 6 层每层 256 个神经元的 SKN，343811 个参数，精度高但计算量大 |
| 学生网络 | 4 层每层 128 个神经元的 SKN，54915 个参数，由教师网络蒸馏得到。主流程的所有实验都用它 |
| 学生引擎 | 学生网络，配合制表查核和 32 个输出时刻。制表查核指先把核在每段端点处算成一张 192 个点的表，之后只查表 |
| 教师引擎 | 教师网络，配合直接查核和 64 个输出时刻，只作为对照 |
| base3、quad4、dense3 | 三个堆叠算例。base3 是主算例，三颗 4 mm 芯片。quad4 是四颗 6 mm 芯片。dense3 是把 base3 的轨间距减半 |
| E0 到 E8 | 九个实验的编号，含义见第 4 节的表 |
| 输出根目录 | `~/stackem_work/outputs`，下文写作 `<输出>` |

## 2. 准备

### 2.1 下载 IBM 基准，可选

IBM 电源网基准是一组公开的真实电源网网表。下载以后，流程里的 `ibmpg` 这一组步骤才会运行，不下载就自动跳过，其他实验不受影响。

```bash
cd ~/StackEM_clean
bash scripts/download_ibmpg.sh
```

脚本下载 ibmpg1 到 ibmpg6 的网表和官方直流解，共约 76 MB，解压后约 610 MB，放在 `~/stackem_work/ibmpg`，最后核对 MD5 校验和。成功时最后一行是：

```text
benchmarks ready in /home/<你的用户名>/stackem_work/ibmpg
```

更详细的说明和出错处理见 [05_IBM基准与COMSOL.md](05_IBM基准与COMSOL.md)。

### 2.2 发布的数据包，可选

仓库里没有放体积较大的两类文件：核数据集和逐轨的应力数组。如果仓库的发布页提供了 `stackem_kernels_dataset.tar` 和 `stackem_per_rail_arrays.tar.gz`，可以下载后在仓库根目录解包，包内路径以 `reference_results/` 开头，会自动归位：

```bash
cd ~/StackEM_clean
tar -xf <下载位置>/stackem_kernels_dataset.tar
tar -xzf <下载位置>/stackem_per_rail_arrays.tar.gz
```

不下载完全没有问题。E1 需要的两个留出核数据集在缺失时由流程里的 `kernels_val` 步骤用参考求解器重新生成，共 500 个剖面，种子固定。逐轨数组每次运行都会重新算出来。

## 3. 运行

1. 打开终端，新建一个 tmux 会话，激活环境。

   ```bash
   tmux new -s stackem
   source ~/stackem_work/venv/bin/activate
   cd ~/StackEM_clean
   ```

2. 启动。

   ```bash
   bash scripts/run_with_released_weights.sh
   ```

3. 按 `Ctrl+B` 再按 `D` 离开会话，任务在后台继续。以后用 `tmux attach -t stackem` 回来查看。

运行期间请不要在同一台机器上同时跑别的计算任务。E4 是测速实验，显卡或处理器被别的任务占用时它测出来的时间就失去意义。

脚本一开始会做下面几件事，屏幕上能看到对应的输出。

1. 核对三个权重文件的 SHA256 校验和，每个文件显示一行 `OK`：

   ```text
   skn_student.npz: OK
   skn_teacher.npz: OK
   skn_teacher_pde.npz: OK
   ```

2. 把权重复制到输出根目录里流程期望的位置：

   | 仓库里的文件 | 复制到 |
   |---|---|
   | `weights/skn_teacher.npz` | `<输出>/base3/skn/skn_best.npz` |
   | `weights/skn_student.npz` | `<输出>/base3/skn_distill/skn_student.npz` |
   | `weights/skn_teacher_pde.npz` | `<输出>/ablation_pde/skn_pde/skn_best.npz` |

3. 把这三个网络的训练记录，也就是摘要、日志和曲线图，从 `reference_results/` 复制到相同的位置，供对比表读取参数量。
4. 把 `kernels`、`train_teacher`、`distill`、`ablation.train` 四个步骤加入跳过清单，然后调用 `scripts/run_all.sh`。

之后每个步骤开始时打印一行带时间和步骤名的标题，结束时打印 `[done] 步骤名 (秒数)`。被跳过的步骤打印 `[skip] 步骤名`。

### 4.7 这些耗时是怎么从日志里读出来的

`reference_results/logs/` 里的日志是参考机上产生发布结果的那几次运行的原样输出。那几次运行把步骤分成了几段依次执行，步骤标题的文字与 `run_all.sh` 现在的步骤名不完全相同，日志里的输出目录写作 `outputs` 和 `outputs_teacher`，分别对应现在的学生引擎结果和教师引擎结果。对应关系如下。

| 现在的步骤 | 日志文件 | 日志里的标题 |
|---|---|---|
| `tests`、`e0`、`e1`、`e2`、`e3`、`e7`、`e4`、`e5`、`e6`、`e8`，`quad4` 的三个实验 | `final_3_full.log` | `unit tests`、`E0 solver + tabulation`、`E1 kernel accuracy (student / tabulated / teacher)` 等 |
| `signoff`、`quad4.signoff`，教师引擎的五个实验 | `final_1_full.log` | `sign-off sizing`、`E1 kernel accuracy`、`E2 rail accuracy`、`E4 scaling` 等 |
| `dense3.signoff`、消融的两个实验 | `final_2_extras.log` | `dense3: sign-off sizing`、`ablation: E1 + E2 ...` |
| `dense3` 的三个实验、`ibmpg.ibmpg1` | `final_4_extras.log` | `dense3: E2 rail accuracy` 等 |
| `ibmpg.ibmpg2` 到 `ibmpg.ibmpg6` | `ibmpg_full.log` | `IBM power-grid benchmark (paper engine): ...` |
| E5 的图 | `e5_redraw.log` | `E5 sensitivity + budget` |

日志如实保留了当时的全部输出，其中有几段运行的结果没有收入 `reference_results/`，例如 `ibmpg_full.log` 开头 ibmpg1 的一次只用处理器的闭合，以及 `final_1_full.log` 里教师引擎在 quad4 上的运行。阅读日志时以 `reference_results/` 里实际存在的文件夹为准。`e5_redraw.log` 对应 `reference_results/base3/e5` 里的文件，其数值与 `final_3_full.log` 里 E5 的输出相同。

## 5. 查看进度

### 5.1 监视脚本

另开一个终端窗口，或者在 tmux 里离开会话以后，输入：

```bash
bash ~/StackEM_clean/tools/monitor.sh
```

它每 20 秒刷新一次，显示当前步骤、最近完成的结果文件、训练进度、显卡和处理器占用、内存、硬盘剩余空间，以及日志的最后十几行。按 `Ctrl+C` 退出监视，正在运行的任务不受影响。

脚本可以带三个参数，依次是算例名、日志文件、输出根目录，都有默认值。例如监视 quad4 的结果文件：

```bash
bash ~/StackEM_clean/tools/monitor.sh quad4
```

### 5.2 直接看日志

所有屏幕输出同时写在 `<输出>/logs/run_all_<启动时间>.log` 里。

```bash
ls -t ~/stackem_work/outputs/logs/
tail -n 30 $(ls -t ~/stackem_work/outputs/logs/run_all_*.log | head -1)
```

第一条列出日志文件，最新的在最前。第二条显示最新日志的最后 30 行。想持续跟踪时把 `tail -n 30` 换成 `tail -f`，按 `Ctrl+C` 停止跟踪。

只看每个步骤的开始和结束：

```bash
grep -E "^=+ |^\[done\]|^\[FAILED\]|^\[skip\]" $(ls -t ~/stackem_work/outputs/logs/run_all_*.log | head -1)
```

### 5.3 结束时的汇总

全部结束后屏幕和日志的末尾有一张表，每个步骤一行，三列分别是步骤名、秒数和状态。状态有四种：`ok`、`skipped`、`skipped(no netlist)`、`FAILED(退出码)`。同一张表另存为 `<输出>/logs/steps_<启动时间>.tsv`。成功的标志是最后两行：

```text
StackEM flow finished: /home/<你的用户名>/stackem_work/outputs (all executed steps succeeded)
compare with the released results:  python tools/check_results.py --root /home/<你的用户名>/stackem_work/outputs
```

## 6. 只跑一部分

两个环境变量控制跑哪些步骤，写在命令最前面。值是用英文逗号隔开的步骤名或组名，中间不要有空格。组名是步骤名里第一个点号之前的部分，写组名等于选中这一组的全部步骤。

| 变量 | 作用 |
|---|---|
| `STACKEM_ONLY` | 只运行列出的步骤或组。它的优先级高于 `STACKEM_SKIP` |
| `STACKEM_SKIP` | 跳过列出的步骤或组，其余照常运行 |

可用的组名有 `quad4`、`dense3`、`teacher`、`ablation`、`ibmpg`、`comsol`、`tables`、`figs`。不带点号的步骤名有 `tests`、`kernels`、`kernels_val`、`train_teacher`、`distill`、`e0` 到 `e8`、`signoff`。

例子：

```bash
# 只重跑 base3 的 E2
STACKEM_ONLY=e2 bash scripts/run_with_released_weights.sh

# 只跑 quad4 这一组的四个步骤
STACKEM_ONLY=quad4 bash scripts/run_with_released_weights.sh

# 只跑 dense3 的 E3 和 E7
STACKEM_ONLY=dense3.e3,dense3.e7 bash scripts/run_with_released_weights.sh

# 跑全部，但跳过耗时最长的教师引擎对照和测速实验
STACKEM_SKIP=teacher,e4 bash scripts/run_with_released_weights.sh

# 只重画图和索引
STACKEM_ONLY=figs bash scripts/run_with_released_weights.sh
```

以 `#` 开头的行是注释，不用输入。

单独跑某一步时要注意它依赖的东西是否已经存在。

| 想单独跑的步骤 | 需要先有 |
|---|---|
| `e0`、`e2`、`e3`、`e4`、`e5`、`e6`、`e8` | `signoff` 的结果 `base3/signoff/signoff_sizing.json` |
| `e7` | 同一算例的 `e3` 结果 |
| `e1` | 两个留出核数据集，由 `kernels_val` 生成 |
| `quad4.e2` 等 | `quad4.signoff` 的结果 |
| `teacher` 组和 `ablation` 组 | base3 的 `signoff` 结果。`teacher.e1` 和 `ablation.e1` 还需要留出核数据集 |
| `teacher.compare` | 两种引擎各自的实验结果 |
| `comsol.export` | base3 的 `e2` 结果 |
| `figs.timing` | base3 的 `e4` 结果 |
| `ibmpg` 组 | 学生网络权重和下载好的网表 |

缺少签核结果时程序不会报错退出，它会打印一行 `[warn] no sign-off sizing found` 并改用配置里的默认轨宽，这样算出来的数字与参考结果不可比。看到这行警告就应当先跑 `signoff`。

`run_with_released_weights.sh` 每次运行都会重新复制权重，重复运行是安全的。已经存在的结果文件会被同名的新结果覆盖。

## 7. 与参考结果比对

### 7.1 命令

```bash
cd ~/StackEM_clean
python tools/check_results.py
```

它把 `~/stackem_work/outputs` 里的每个摘要 JSON 与 `reference_results/` 里的同名文件逐个数字比较，只用到 Python 标准库，几秒钟完成。输出根目录不在默认位置时用 `--root <目录>` 指定。加 `-v` 会列出每一个有偏差的数字。

### 7.2 输出怎么读

每个摘要文件一行。下面是示意，三行分别展示完全一致、有容差内的微小偏差、没有运行三种情况：

```text
experiment file                                status    values  differ  worst deviation
base3/e2/e2_summary.json                       PASS         400       0  largest relative deviation 0.0e+00
base3/signoff/signoff_sizing.json              PASS          61       0  largest relative deviation 1.6e-04
comsol/comsol_rails_compare.json               not run
```

| 列或状态 | 含义 |
|---|---|
| `values` | 这个文件里参与比较的数字个数 |
| `differ` | 超出容差的数字个数 |
| `PASS` | 所有参与比较的数字都在容差之内 |
| `DIFF` | 至少一个数字超出容差。同一行会显示偏差最大的那个数字的位置、参考值和新值 |
| `not run` | 参考结果里有这个文件，你的输出里没有，也就是这个实验没有跑 |
| `ERROR` | 文件读不出来，通常是运行中断留下了不完整的文件 |

最后一行是总计，形如 `34 PASS, 0 DIFF, 0 not run`。参考结果里一共有 34 个参与比对的摘要文件。只要有一个 `DIFF`，命令的退出状态就是 1。

### 7.3 比较的规则

数字按来源分成三类，宽严不同。

| 类别 | 哪些数字 | 规则 |
|---|---|---|
| REF | 参考求解器、HotSpot、供电网求解给出的数字，例如真值的成核时间、成核轨数、轨宽、温度 | 整数必须相等。小数的相对容差默认 0.001。签核记录的最早成核时间放宽到 0.005，E0 的自检误差放宽到 0.05 |
| SUR | 网络加闭合给出的数字，例如精度指标、预测的成核时间、排序指标 | 小数允许相对 0.02 加绝对 0.0002 的偏差，整数必须相等 |
| TIME | 墙钟秒数、设备名、线程数、命令行、日期 | 不比较 |

### 7.4 哪些差异是预期之中的

1. 所有耗时都不参与比较。你的机器与参考机不同，秒数必然不同。`e4_timing.json` 只核对规模和设置是否相同。
2. 签核文件里的轨宽应当与参考完全一致。记录的“该轨宽下最早成核时间”允许有千分之一以内的偏差，因为发布的签核文件是用 64 个输出时刻算的，现在的流程统一用 `configs/base3.json` 里的 32 个。E3 和 E5 的摘要里带有同一份签核记录，所以也会显示同样大小的偏差。
3. E1 用的两个留出核数据集如果是你自己重新生成的，核精度的数字可能在很靠后的有效数字上有差别，远小于容差。
4. `comsol/comsol_rails_compare.json` 显示 `not run` 是正常的，除非你做了 COMSOL 交叉验证，见 05 号文档。
5. 没有下载 IBM 基准时，六个 `ibmpg/.../ibmpg_summary.json` 显示 `not run`。
6. 用 `STACKEM_SKIP` 跳过的实验显示 `not run`。
7. 没有显卡不影响比对。闭合在显卡上还是处理器上运行不改变精度数字，设备名不参与比较。

下面的情况会出现 `DIFF`，需要你查明原因。

1. 在没有签核结果的情况下单独跑了某个实验，见第 6 节的警告。
2. 用环境变量改过设置，例如 `STACKEM_E4_SIZES`。
3. 修改过配置文件或代码。
4. 某一步中途被杀，留下了旧的或不完整的结果。

如果一切按本文操作仍然出现 `DIFF`，请用 `-v` 列出全部偏差，对照第 7.3 节判断它属于哪一类，再查看那一步的日志。软件版本与 01 号文档的版本表不同时，参考求解器的数字也可能出现略超容差的偏差，这种情况可以用 `--ref-tol` 放宽后再比，例如 `python tools/check_results.py --ref-tol 0.005`，并在引用结果时说明。
