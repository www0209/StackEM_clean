# 08 代码与文件说明

本文是仓库的地图：每个文件夹和文件是做什么的，`stackem/` 里每个模块有哪些函数、被谁调用，每个配置键的含义和取值，`scripts/run_all.sh` 每一步执行的确切命令和写出的文件，每个环境变量，输出目录和 `reference_results/` 的布局，每种结果文件里有哪些键，单元测试，以及怎样在 Python 里加载 `weights/` 下的网络。

读法约定：

- 路径都相对仓库根目录。`<root>` 指输出根目录，默认 `~/stackem_work/outputs`。`<case>` 指算例目录名，如 `base3`。
- 取自结果文件和日志的数字登记在 `docs/checks/08_代码与文件说明.jsonl`，可用 `python3 tools/verify_docs.py docs/checks/08_代码与文件说明.jsonl` 复核。
- 方法和术语见 [06_思路与方法.md](06_思路与方法.md)，设计选择见 [07_设计选择与简化.md](07_设计选择与简化.md)。

| 路径 | 内容 |

## 2. `stackem/` 软件包

依赖关系自下而上分四层：常数与单段物理，求解器与闭合，堆叠级流程，实验入口。只有 `closure_torch.py`、`train_skn.py`、`train_distill.py` 和 `sensitivity.py` 的可微部分需要 PyTorch，其余只需要 numpy 和 scipy。

| 参数 | 含义 |

## 3. 配置文件

配置是 json 文件。`config.py:load_config` 先复制 `DEFAULT_CONFIG`，再用文件内容递归覆盖：字典逐键合并，列表整体替换。所以一个配置文件只需要写与默认不同的键。`configs/base3.json` 把全部键都写了出来，单元测试 `test_shipped_configs` 检查它与 `DEFAULT_CONFIG` 一致。

五个文件：

| 文件 | 用途 |
|---|---|
| `base3.json` | 主算例，学生引擎 |
| `quad4.json` | 第二个堆叠：四颗 6 mm 芯片 |
| `dense3.json` | base3 的堆叠，格距加密到 50 µm |
| `base3_teacher.json` | 教师引擎对照；方程残差消融也用它，另加 `--out-name ablation_pde` |
| `smoke.json` | 功能测试用的缩小设置，可以合并在其他配置之后 |

### 4.2 冒烟模式的差别

`STACKEM_MODE=smoke`，也就是 `run_smoke.sh`，执行同样的步骤，差别是：

- 主配置换成 `configs/smoke.json`，输出目录名是 `smoke`；quad4 和 dense3 用 `configs/quad4.json,configs/smoke.json` 这样的合并配置；教师引擎对照的目录名是 `smoke_teacher`。
- 每个实验都带 `--smoke`：2000 个核剖面，教师 8 轮，E2 和 E3 每颗芯片只解几条轨，E4 只测 24 和 82 条轨。
- 蒸馏用 `--epochs 3 --n-synthetic 200000 --hidden 32,32 --fourier 8`。
- IBM 一组改为 `ibmpg.synthetic`，用程序生成的小网表。

冒烟运行的数字没有物理意义，只看最后是否全部成功。

### 4.3 `run_with_released_weights.sh` 做了什么

1. 检查 `weights/` 下三个 npz 是否存在，并用 `sha256sum -c SHA256SUMS` 核对。
2. 复制权重：`skn_teacher.npz` 到 `<root>/base3/skn/skn_best.npz`，`skn_student.npz` 到 `<root>/base3/skn_distill/skn_student.npz`，`skn_teacher_pde.npz` 到 `<root>/ablation_pde/skn_pde/skn_best.npz`。
3. 把 `reference_results/` 里三个训练目录的训练记录复制到输出目录的对应位置，npz 除外。对照表要从这些记录里读参数个数。
4. 若 `reference_results/base3/kernels/` 下有核数据的 npz，就复制到输出目录。
5. 把 `kernels,train_teacher,distill,ablation.train` 加进 `STACKEM_SKIP`，然后执行 `run_all.sh`。

E1 需要两个留出核集。它们不在输出目录时，`kernels_val` 步会用参考求解器重新生成，共 500 个剖面，不生成训练集。

| `skn_student.npz` | 学生，4 层 128 宽，主流程使用的网络 |

### 9.2 在 Python 里加载和使用

下面的例子只需要 numpy 和 scipy。它读入学生，做一次前向，再造一条 6 段的轨，分别用闭合和参考求解器求成核时间。把它存成任意位置的文件，例如 `~/stackem_work/demo_weights.py`，然后在仓库根目录运行 `PYTHONPATH=. python ~/stackem_work/demo_weights.py`。

```python
import numpy as np
from stackem.constants import default_em, default_thermal, SEC_PER_YEAR
from stackem.power_grid import Rail
from stackem.skn_model import SKNWeights, forward_numpy
from stackem.skn_numpy import SKNNumpyProvider
from stackem.closure_tab import wrap_provider
from stackem.closure import close_rails
from stackem.assembler import solve_rails_truth

# 1. 读权重，看结构
w = SKNWeights.load("weights/skn_student.npz")
n_params = sum(a.size for a in w.W) + sum(b.size for b in w.b)
print(w.cfg.hidden, w.cfg.n_fourier, n_params)          # [128, 128, 128, 128] 16 54915

# 2. 直接前向：输入 xi, log10_tau, theta, r, rho_J, lam，输出三个缩放后的核
X = np.array([[1.0, -2.0, 0.0346, 0.0, 0.0, 14.45]])
print(forward_numpy(w, X))

# 3. 包成闭合使用的核提供者，制表 192 点，与主流程相同
provider = wrap_provider(SKNNumpyProvider(w), "tabulated", 192)

# 4. 造一条 6 段的轨，分别用闭合和参考求解器求成核时间
em, th = default_em(), default_thermal()
S = 6
L = np.full(S, 100e-6)                                   # 每段 100 um
j = 8e9 * np.linspace(1.0, 0.4, S)                       # 电流密度 A/m^2
Tn = 360.0 + np.linspace(-4.0, 4.0, S + 1)               # 七个节点的温度 K
Tm = th.T_m(np.abs(j), True)                             # 焦耳鼓包幅值
sigma_T = np.asarray(em.sigma_T(0.5 * (Tn[:-1] + Tn[1:])))
rail = Rail("demo", "H", 0, 0.0, 0.0, L, 2e-6, 1e-6, j, Tn[:-1], Tn[1:], Tm, th.Gamma(True), sigma_T, np.zeros(S + 1, bool))
times = np.logspace(4.0, 9.5, 32)                        # 主流程的 32 个输出时刻

t_closure = close_rails([rail], em, provider, times).t_nuc[0]
_, t_truth, _ = solve_rails_truth([rail], em, times, 60)
print(t_closure / SEC_PER_YEAR, t_truth[0] / SEC_PER_YEAR)
```

屏幕上应出现三行。第一行是 `[128, 128, 128, 128] 16 54915`。第二行是三个缩放后的核值，约为 1.128、-0.0017、-0.0009；第一个数乘以 sqrt(0.01) 就是 s_G 在右端、τ 为 0.01 处的值 0.1128。第三行是两个成核时间，闭合约 0.527 年，参考求解器约 0.528 年。

说明：

- `forward_numpy` 的输出是除以 sqrt(τ) 之后的量，s_M 还除了幅值估计。要拿到真正的核值，用 `SKNNumpyProvider.evaluate(desc, xi, tau)`，它返回键为 `a`、`s_G`、`s_M` 的字典，并处理训练范围之外的情形。
- 换成教师只需把文件名改成 `weights/skn_teacher.npz`，其余不变。
- 装有 PyTorch 时，`stackem.skn_model.SKN.from_weights(w)` 把同一份权重变成 PyTorch 模块，`stackem.closure_torch.SKNTorchProvider(w, device)` 是对应的核提供者。
- 运行脚本时不需要手动加载：`run_with_released_weights.sh` 会把这三个文件复制到输出目录里实验脚本默认寻找的位置。

## 10. `tools/`

| 文件 | 作用 | 用法 |
|---|---|---|
| `run_ibmpg.py` | IBM 网表的完整流程，见 [06_思路与方法.md](06_思路与方法.md) 第 15 节 | `python tools/run_ibmpg.py --spice <网表> --config configs/base3.json`；`--synthetic` 用程序生成的小网表；`--cpu` 强制用 numpy 闭合；`--unit` 手动指定坐标单位；`--no-thermal`、`--uniform-T`、`--sigma-T0`、`--tag`、`--strap-width-um`、`--strap-thickness-um`、`--die`、`--workers` 用于改变假设 |

| `compare_engines.py` | 教师引擎与学生引擎的对照表和两张对照图 | 由 `teacher.compare` 步调用 |
| `param_table.py` | 从配置和常数生成参数表 | 由 `tables.*` 步调用 |
| `framework_figure.py` | 程序化绘制流程框图 | 由 `figs.framework` 步调用 |
| `paper_timing_fig.py` | 从 E4 的结果画只含一个引擎的速度图，可叠加外部曲线 | 由 `figs.timing` 步调用 |
| `collect_figures.py` | 把一个算例的图和汇总文件集中复制并写索引 | 由 `figs.index_*` 步调用 |
| `monitor.sh` | 在第二个终端里每 20 秒刷新一次运行状态：当前步骤、已完成的输出、训练进度、GPU 和 CPU 占用、日志末尾 | `bash tools/monitor.sh [算例] [日志] [输出根目录]`，按 Ctrl+C 退出，不影响运行 |
| `verify_docs.py` | 按 `docs/checks/*.jsonl` 复核文档里的数字 | `python3 tools/verify_docs.py` 或指定某个清单文件 |
| `check_links.py` | 检查所有 markdown 文件里的相对链接和图片是否指向存在的文件 | `python3 tools/check_links.py --strict` |

`check_results.py` 对不同来源的数用不同的严格程度：参考求解器、HotSpot、供电网算出的整数必须相等，浮点数相对容差 1e-3；替身算出的数在使用发布权重时容差 2 %，重新训练后只要求同一量级；用时、设备名、命令行、日期从不比较。

`docs/checks/` 下每个清单文件的每一行是一个 json 对象：`doc` 是引用该数字的文档，`claim` 是说明，`value` 是文档里印出的值，可选的 `scale` 是原始值到印出值的换算因子，`digits` 是印出的小数位数；数据来源三选一：`file` 加 `path` 指 json 文件里的键路径，`file` 加 `regex` 指文本文件里的正则匹配，`py` 是一个 Python 表达式。
