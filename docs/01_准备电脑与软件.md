# 01 准备电脑与软件

本文带你从一台普通的电脑走到“仓库已经放在正确的位置，终端已经会用”。读完并做完以后，接着读 [02_安装.md](02_安装.md)。

文中所有命令都放在代码框里。代码框里的内容照原样输入，一行一条，每输入一行按一次回车。尖括号括起来的部分例如 `<仓库地址>` 需要换成你自己的内容，尖括号本身不要输入。

文中凡是来自日志或结果文件的数字，都登记在 `docs/checks/01_准备电脑与软件.jsonl`，可用 `python3 tools/verify_docs.py docs/checks/01_准备电脑与软件.jsonl` 复核。

## 1. 选哪台电脑

### 1.1 参考机

本仓库 `reference_results/` 里的全部结果和 `reference_results/logs/` 里的全部耗时，都来自同一台机器，下文称为参考机。

| 项目 | 参考机 |
|---|---|
| 操作系统 | Windows 11，计算在 WSL2 里的 Ubuntu 24.04 中进行 |
| 处理器 | AMD Ryzen 9 9950X，16 核 32 线程 |
| 内存 | 61.5 GB，其中 WSL 里可见约 30 GB |
| 显卡 | NVIDIA GeForce RTX 4070 Ti SUPER，显存 16 GB |
| Python | 3.11.16 |
| PyTorch | 2.14.0，CUDA 13.0 版本 |
| COMSOL | 6.2，配 LiveLink for MATLAB，MATLAB 版本 R2024a，装在 Windows 一侧，只用于可选的交叉验证 |

WSL2 是 Windows 自带的 Linux 虚拟机，装好以后可以在 Windows 里打开一个 Ubuntu 终端窗口，像用一台 Linux 电脑一样输入命令。日志里写的 32 cores 和 32 workers 指的是 32 个线程。

### 1.2 最低配置与推荐配置

| 项目 | 最低 | 推荐 |
|---|---|---|
| 处理器 | 4 核 | 16 核或更多 |
| 内存 | Linux 一侧可用 16 GB | Linux 一侧可用 30 GB 或更多 |
| 显卡 | 可以没有 | NVIDIA 显卡，显存 16 GB |
| 硬盘剩余空间 | 20 GB | 40 GB |
| 网络 | 安装时需要联网 | 同左 |

最低配置一栏是保守的建议值，本仓库没有在这样的机器上测量过完整流程的耗时。有实测记录的只有两种情况：参考机，以及 `scripts/run_smoke.sh` 的注释里记录的一台 2 核无显卡的机器，后者跑完冒烟测试用了 45 到 70 分钟。

硬盘空间的主要去向如下，供你估算。

| 内容 | 位置 | 大小 |
|---|---|---|
| 仓库本身 | `~/StackEM_clean` | 约 72 MB |
| Python 环境，含带显卡支持的 PyTorch | `~/stackem_work/venv` | 约 6 GB |
| IBM 基准，可选 | `~/stackem_work/ibmpg` | 下载约 76 MB，解压后约 610 MB |
| 运行输出，路线 A | `~/stackem_work/outputs` | 1 到 2 GB |
| 核训练集，只有路线 B 会生成 | `~/stackem_work/outputs/base3/kernels` | 数百 MB |
| pip 的下载缓存 | `~/.cache/pip` | 数 GB，装完可以删 |

### 1.3 处理器核数少会怎样

参考求解器会把轨分给所有的核并行计算，核越多越快。可以用参考机上的一组实测数字感受差距：两万条轨，32 线程用 28.4 秒，单核用 490.4 秒。所以在 4 核的机器上，以参考求解器为主的步骤会比参考机慢好几倍。HotSpot 是单线程的，它的耗时与核数无关。

### 1.4 没有 NVIDIA 显卡会怎样

没有 NVIDIA 显卡时，安装脚本会自动装上只用处理器的 PyTorch，所有步骤仍然能运行，结果的数值不受影响，只是下面几处会变慢。

| 环节 | 有显卡，参考机实测 | 没有显卡 |
|---|---|---|
| IBM 基准 ibmpg1 的闭合，1942 条轨 | 2.6 秒 | 51.4 秒，参考机用处理器实测 |
| E4 里 1000 条轨的闭合 | 1.2 秒 | 77.8 秒，参考机用处理器实测 |
| 教师网络训练，300 轮 | 1345 秒 | 没有测量过，预计长很多倍 |
| 学生网络蒸馏，150 轮 | 332 秒 | 没有测量过 |
| 带方程残差项的消融训练 | 11080 秒 | 没有测量过，不建议尝试 |

因此没有显卡的读者请走路线 A，即使用发布的权重，不要自己训练。E4 是测速实验，在没有显卡的机器上它测到的是处理器的速度，与参考结果的耗时不可比，这是正常的。

AMD 或 Intel 的显卡不能用于本项目的显卡加速，按没有显卡处理。

### 1.5 各种选择大约要多久

下表的时间是把参考机日志里各步的耗时相加得到的，明细见 [03_复现实验_使用发布的权重.md](03_复现实验_使用发布的权重.md) 和 [04_复现实验_从零开始.md](04_复现实验_从零开始.md)。

| 你要做的事 | 参考机上的耗时 |
|---|---|
| 安装环境 | 约 10 分钟，取决于网速 |
| 冒烟测试 | 没有在参考机上计时。2 核无显卡的机器上是 45 到 70 分钟，工作站会快几倍 |
| 路线 A，使用发布的权重跑全部实验，含 IBM 基准 | 约 3.0 小时 |
| 路线 B，从零开始，含生成数据、三次训练和全部实验 | 约 6.6 小时 |

路线 A 里最耗时的是教师引擎对照这一组，参考机上约 1.4 小时。如果只关心主流程，可以跳过它，办法见 03 号文档。

## 2. 选哪种操作系统

有两种选择，效果相同。

| 选择 | 适合谁 | 说明 |
|---|---|---|
| Windows 11 加 WSL2 里的 Ubuntu 24.04 | 平时用 Windows 的读者 | 与参考机相同。COMSOL 交叉验证也在同一台电脑的 Windows 一侧完成 |
| 直接安装 Ubuntu 24.04 或 22.04 | 已经有 Linux 电脑或服务器的读者 | 跳过下面第 3 节，从第 4 节开始 |

## 3. 在 Windows 11 上安装 WSL2 和 Ubuntu 24.04

已经在用原生 Ubuntu 的读者跳过本节。

### 3.1 安装 WSL2 与 Ubuntu

1. 点击屏幕下方的开始按钮，在搜索框里输入 `PowerShell`。
2. 在搜索结果的“Windows PowerShell”上点鼠标右键，选择“以管理员身份运行”。弹出的确认框点“是”。会出现一个蓝色或黑色的窗口，这就是 PowerShell。
3. 在窗口里输入下面这一行，然后按回车。

   ```powershell
   wsl --install -d Ubuntu-24.04
   ```

   这条命令做两件事：打开 Windows 的 WSL2 功能，下载并安装 Ubuntu 24.04。屏幕上会显示下载进度，需要几分钟到十几分钟。
4. 命令结束后如果提示需要重启，就重启电脑。
5. 重启后 Ubuntu 的窗口通常会自动弹出并继续安装。如果没有弹出，点开始按钮，搜索 `Ubuntu`，点击打开。
6. 第一次打开时它会让你起一个用户名并设置密码：

   ```text
   Enter new UNIX username:
   New password:
   Retype new password:
   ```

   用户名用小写英文字母，例如 `stack`。输入密码时屏幕上什么都不显示，这是正常的，输完按回车即可。这个密码以后安装软件时会用到，请记住。
7. 看到类似下面这样以 `$` 结尾的一行，就说明 Ubuntu 已经可以用了。这一行叫提示符，表示它在等你输入命令。

   ```text
   stack@mypc:~$
   ```

### 3.2 确认用的是 WSL2

回到 PowerShell 窗口，输入：

```powershell
wsl -l -v
```

应当看到类似下面的输出，`VERSION` 一列是 2。

```text
  NAME            STATE           VERSION
* Ubuntu-24.04    Running         2
```

如果是 1，输入 `wsl --set-version Ubuntu-24.04 2` 转换。

### 3.3 给 WSL 更多内存，可选但建议

WSL2 默认只把电脑内存的一半左右分给 Linux。参考机有 61.5 GB 内存，WSL 里可见约 30 GB。如果你的电脑内存是 32 GB，默认情况下 Linux 里只有大约 16 GB。想多分一些时这样做：

1. 在 Windows 里按 `Win+R`，输入 `notepad %UserProfile%\.wslconfig`，回车。提示文件不存在时选择新建。
2. 在记事本里写入下面三行并保存。数字按你的电脑调整，给 Windows 自己至少留 8 GB。

   ```text
   [wsl2]
   memory=24GB
   swap=8GB
   ```

3. 在 PowerShell 里输入 `wsl --shutdown`，然后重新打开 Ubuntu 窗口，设置生效。

### 3.4 安装 NVIDIA 显卡驱动并在 WSL 里检查

没有 NVIDIA 显卡的读者跳过这一小节。

1. 驱动装在 Windows 一侧。用浏览器打开 NVIDIA 官方网站的驱动下载页，选择你的显卡型号和 Windows 11，下载并按提示安装最新的驱动，装完重启。
2. 不要在 Ubuntu 里再安装任何 NVIDIA 驱动。WSL 会直接使用 Windows 一侧的驱动。也不需要单独安装 CUDA 工具包，PyTorch 自带它需要的运行库。
3. 打开 Ubuntu 窗口，输入：

   ```bash
   nvidia-smi
   ```

   应当看到一张表格，里面有显卡的名称和显存大小，例如显存一栏写着 `16376MiB`。看到这张表就说明显卡在 WSL 里可用。
4. 如果提示 `command not found` 或者报错，先确认 Windows 的显卡驱动已是最新，再在 PowerShell 里执行 `wsl --update` 和 `wsl --shutdown`，然后重新打开 Ubuntu 再试。仍然不行也可以继续往下做，安装脚本会按没有显卡处理。

原生 Ubuntu 的读者需要自己安装 NVIDIA 的 Linux 驱动，最简单的办法是在终端里执行 `sudo ubuntu-drivers install`，重启后同样用 `nvidia-smi` 检查。

## 4. 打开终端与基本操作

### 4.1 打开终端

| 系统 | 做法 |
|---|---|
| Windows 加 WSL | 点开始按钮，搜索 `Ubuntu`，点击打开。本文以后说的终端都指这个窗口 |
| 原生 Ubuntu | 同时按 `Ctrl+Alt+T` |

### 4.2 必须会的几条命令

终端里你始终“站在”某个文件夹里，这个文件夹叫当前目录。波浪号 `~` 代表你的家目录，也就是 `/home/<你的用户名>`。

| 命令 | 作用 | 例子 |
|---|---|---|
| `pwd` | 显示当前目录 | `pwd` |
| `ls` | 列出当前目录里的文件和文件夹 | `ls`，或 `ls ~/stackem_work` |
| `cd <目录>` | 进入某个目录 | `cd ~/StackEM_clean` |
| `cd ..` | 回到上一级目录 | `cd ..` |
| `cd` | 回到家目录 | `cd` |
| `cat <文件>` | 把一个文本文件的内容显示出来 | `cat scripts/requirements.txt` |
| `less <文件>` | 翻页查看长文件，按 `q` 退出 | `less setup_env.log` |
| `tail -n 20 <文件>` | 显示文件的最后 20 行 | `tail -n 20 setup_env.log` |
| `df -h ~` | 查看硬盘剩余空间 | `df -h ~` |
| `free -g` | 查看内存，单位 GB | `free -g` |
| `nproc` | 查看处理器线程数 | `nproc` |

几个省力的技巧：

1. 输入路径时按 `Tab` 键可以自动补全。
2. 按方向键的上箭头可以调出上一条命令。
3. 命令前面带 `sudo` 表示以管理员身份执行，会要求输入你在 3.1 节设置的密码，输入时同样不显示。

### 4.3 复制与粘贴

| 操作 | Windows 的 Ubuntu 窗口 | 原生 Ubuntu 终端 |
|---|---|---|
| 粘贴 | 点鼠标右键，或按 `Ctrl+Shift+V` | `Ctrl+Shift+V` |
| 复制 | 用鼠标选中文字后点右键，或按 `Ctrl+Shift+C` | `Ctrl+Shift+C` |

注意 `Ctrl+C` 在终端里的意思是中断正在运行的命令，不是复制。

### 4.4 中断一条命令

命令运行中想让它停下，按 `Ctrl+C`。提示符重新出现就表示已经停了。

### 4.5 用 tmux 运行长任务

本项目有的步骤要跑几个小时。如果直接在终端里运行，关掉窗口或者远程连接断开，任务就会被终止。tmux 可以让任务在后台的会话里继续跑，窗口关了也不受影响。安装脚本会装好 tmux，下面是全部需要的操作。

| 目的 | 做法 |
|---|---|
| 新建一个名叫 stackem 的会话 | `tmux new -s stackem` |
| 离开会话，让里面的任务继续跑 | 先按 `Ctrl+B`，松开，再按 `D` |
| 回到会话 | `tmux attach -t stackem` |
| 查看有哪些会话 | `tmux ls` |
| 在会话里向上翻看输出 | 先按 `Ctrl+B`，松开，再按 `[`，然后用方向键或翻页键，按 `q` 退出翻看 |
| 结束会话 | 在会话里输入 `exit` |

使用顺序是：新建会话，在会话里输入运行命令，离开会话，之后随时回来查看。

Windows 用户还要注意一点：电脑睡眠或关机时 WSL 会停止，tmux 里的任务也会停。跑长任务之前请在 Windows 的电源设置里把“睡眠”改成“从不”。

## 5. 安装 git

git 是下载和管理代码仓库的工具。在终端里输入：

```bash
sudo apt-get update
sudo apt-get install -y git
git --version
```

第一条更新软件清单，第二条安装 git，第三条显示版本号。看到类似 `git version 2.43.0` 的一行就表示装好了。这一步需要一两分钟。

## 6. 把仓库放到 `~/StackEM_clean`

后面所有文档都假设仓库在 `~/StackEM_clean`。两种办法任选其一。

### 6.1 办法一：git clone

1. 在浏览器里打开仓库的网页，点绿色的“Code”按钮，复制 HTTPS 一栏里的地址。
2. 在终端里输入下面的命令。命令里的地址就是本仓库的地址，如果你复制到的地址不同，以复制到的为准。

   ```bash
   git clone https://github.com/www0209/StackEM_clean.git ~/StackEM_clean
   ```

   这条命令把整个仓库下载到 `~/StackEM_clean`。仓库约 72 MB，通常一两分钟。结束时会看到 `Receiving objects: 100%` 和 `Resolving deltas: 100%` 两行。
3. 如果下载中途断开，删掉残留的文件夹再来一次：

   ```bash
   rm -rf ~/StackEM_clean
   git clone https://github.com/www0209/StackEM_clean.git ~/StackEM_clean
   ```

### 6.2 办法二：下载 zip 压缩包

1. 在仓库网页上点绿色的“Code”按钮，选择“Download ZIP”。浏览器会把压缩包存到 Windows 的“下载”文件夹。
2. 在终端里先安装解压工具：

   ```bash
   sudo apt-get install -y unzip
   ```

3. 把压缩包从 Windows 复制到 Linux 的家目录并解压。Windows 的 C 盘在 WSL 里的位置是 `/mnt/c`。把命令里的 `<Windows用户名>` 和 `<压缩包文件名>` 换成实际的名字，可以用 `ls /mnt/c/Users/` 和 `ls /mnt/c/Users/<Windows用户名>/Downloads/` 查看。

   ```bash
   cp /mnt/c/Users/<Windows用户名>/Downloads/<压缩包文件名>.zip ~/
   cd ~
   unzip <压缩包文件名>.zip
   ```

4. 解压出来的文件夹名字通常带有分支名的后缀。用 `ls ~` 看一下它叫什么，然后把它的名字换成 `StackEM_clean`：

   ```bash
   mv ~/<解压出来的文件夹名> ~/StackEM_clean
   ```

请务必把仓库放在 Linux 的家目录下，不要放在 `/mnt/c` 这样的 Windows 盘上。在 Windows 盘上读写文件很慢，脚本的可执行权限也可能出问题。

### 6.3 检查

```bash
cd ~/StackEM_clean
ls
```

应当看到下面这些名字：

```text
LICENSE  README.md  comsol  configs  docs  reference_results  scripts  stackem  third_party  tools  weights
```

## 7. 全部做完以后的文件夹布局

仓库和工作目录是分开的。仓库只读，所有运行产生的东西都在工作目录 `~/stackem_work` 里。下面是装完并运行之后的样子，其中 `~/stackem_work` 及其子文件夹由 02 号文档里的安装脚本和之后的运行脚本自动创建，现在还不存在。

```text
~/StackEM_clean/                 仓库，不要在里面存放自己的结果
    README.md  LICENSE
    docs/                        文档
    stackem/                     代码包
    configs/                     算例配置
    scripts/                     安装与运行脚本
    tools/                       辅助工具
    comsol/                      可选的 COMSOL 交叉验证
    third_party/                 HotSpot 源码压缩包
    weights/                     发布的网络权重
    reference_results/           参考结果与日志

~/stackem_work/                  工作目录
    venv/                        Python 虚拟环境
    HotSpot/                     编译好的 HotSpot 热仿真器
    outputs/                     正式运行的输出，结构与 reference_results/ 相同
        base3/  quad4/  dense3/  base3_teacher/  ablation_pde/  ibmpg/  comsol/  logs/
    outputs_smoke/               冒烟测试的输出
    ibmpg/                       IBM 基准网表，可选
```
